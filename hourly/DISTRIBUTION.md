# Post-publish distribution — what fires after every piece, automatically

*Companion to README.md (recipe) and DESIGN.md (architecture). This is the publisher stage's second half: the piece is live — now make sure the searchers and the feeds find it while the spike is still climbing. Everything in Tier 1–2 runs unattended; Tier 3 is deliberately manual; Tier 4 is prohibited.*

**Governing rule (from AVAULT §2.4/§9.5):** no undisclosed automation, no dark distribution. Auto-posting to *our own, clearly-owned channels* is disclosed automation and is fine. Auto-posting into *other people's spaces* (subreddits, comment sections, forums) is not — at any volume.

---

## Tier 1 — The indexing race (highest effect; all free; fire within 60s of publish)

Search is the product's primary channel; these decide whether the piece enters Google/Bing while the query is still spiking.

1. **Google News sitemap** (`news-sitemap.xml`) — THE lever for hourly news content. `<news:news>` entries for pieces from the **last 48h only** (spec limit), with `news:publication_date` to the minute. Google crawls news sitemaps of active news sites every few minutes. Regular sitemap keeps the permanent record; the news sitemap is the fast lane. One-time: add to GSC.
2. **IndexNow ping** — instant push to Bing/Yandex/Naver/Seznam. Infra already exists on metatake.net (key + script); add the new URL per publish. Near-zero cost, guaranteed freshness on the non-Google engines.
3. **NewsArticle JSON-LD + OG tags** — `NewsArticle` (not `Article`) with `dateModified`, `author` → Wonwoo Yoon Person entity; `og:image` 1200×630 auto-generated card (see Tier 2). Required for Top Stories eligibility and Google Discover (Discover wants large images: also set `max-image-preview:large`).
4. **GSC sitemap submit via API** (`sitemaps.submit`, service account) — once at setup, then re-submit daily by cron for hygiene. **Note the honest limits:** per-URL "Request Indexing" in the GSC UI has no official automatable equivalent — the Indexing API is restricted to JobPosting/BroadcastEvent and abusing it risks a manual action; the old sitemap-ping endpoint was retired in 2023. News sitemap + frequent natural crawl IS the legitimate fast path.
5. **RSS/Atom feed for the `/now` section** — updated per publish. Free ecosystem distribution (feed readers, Flipboard-class aggregators) and a crawl signal.

**One-time manual (Wonwoo, ~30min):** Bing Webmaster Tools verification, `max-image-preview:large` site-wide check. **Correction (2026-07-08, verified):** Google Publisher Center no longer accepts publication submissions (removed Apr 2024) — Google News/Top Stories inclusion is fully algorithmic and typically takes ~2 years of news-publisher classification. The news sitemap still matters (crawl speed + Discover), but there is nothing to apply to. See FORECAST.md.

## Tier 2 — Own-channel social fan-out (automated, disclosed, per-piece)

Social links are nofollow — the value is distribution, brand, and the discovery loop (people who see it, search it, click it), not direct SEO. Cost-ranked:

| Channel | How | Cost | Verdict |
| :-- | :-- | :-- | :-- |
| **Bluesky** | official API, app password, trivial post | $0 | ✅ Auto-post every piece |
| **Telegram channel** | Bot API `sendMessage` with link preview | $0 | ✅ Auto-post every piece — doubles as the real-time subscriber push (email stays daily) |
| **Mastodon** | official API | $0 | ✅ Auto-post every piece (small audience, zero marginal cost) |
| **X** | — | — | ❌ **Dropped (Wonwoo, 2026-07-08).** Evidence: <1K non-Premium accounts get median <100 impressions and 0% median engagement on link posts (Buffer, 18.8M posts); bulk bare-link posting matches X's stated spam pattern; $0.20/URL-post surcharge. Not built |
| **Threads** | publishing API exists (Apr 2026 update) | $0 | ○ Optional; audience fit unproven — add once the big four run |
| LinkedIn | API painful, token churn | $0 | ✗ Manual only, occasional AVAULT-brand pieces |

**Post format (all channels, generated by the pipeline):** headline + one-line thesis (not clickbait) + the film hook ("The film that already staged this: *Quiz Show*") + link + auto-generated OG card. The card is text-design only — **no film stills** (rights). Vary wording per channel; never post the identical string everywhere (spam heuristics).

## Tier 3 — Human-only amplification (never automated)

- **Reddit** — do NOT auto-post, ever. Subreddit self-promotion rules + karma heuristics mean an account posting its own domain hourly gets banned and **the domain gets sitewide-blacklisted**, which also poisons the free early-warning signal we poll. If used at all: Wonwoo, manually, rarely, as a genuine community member (r/TrueFilm, r/flicks) when a piece truly serves a thread. The 4-lever brand version of this rule: forced distribution is the same failure as a forced rhyme.
- **Hacker News** — same logic for tech pieces; occasional manual submit only.
- **Outreach emails** — stay per-piece human-approved (AVAULT §5.6–5.8), attached to daily-curated pieces only, cap 30/day. This remains the highest-leverage link-earning channel and must stay craftwork.

## Tier 4 — Prohibited (product boundary, AVAULT §9.5)

No comment-section posting, no auto-DMs, no engagement pods, no cross-posting to platforms as if human, no undisclosed syndication (Medium/etc. duplicates also create canonical risk). The system contains no code for these paths.

## The internal loop (site work, automated, compounds SEO)

1. **Reverse film link:** each `/now` piece already links its film; the film page gets an **"In the news"** module surfacing recent `/now` pieces that cite it (query by film slug, ISR-cached). Every chase deposits permanent internal-link equity into the corpus — this is the moat portal abusers don't have.
2. **Related pieces:** `/now` piece → same trope/figure pieces + the film's tropes (existing connection engine).
3. **Daily digest:** the curated email (Substack) = best 3–5 of the stream; each digest item links the `/now` originals.

## Feedback loop (automated, read-only)

- **GSC 24-hour hourly view** per piece: did it earn impressions within 6h? Feeds the 14-day zero-impression **pruning job** (README SEO posture).
- Per-channel click coalescing (UTM per channel: `?utm_source=x|bsky|tg`) so the ledger can record which channels actually move readers.
- Weekly: which figure/film/verdict types earn Discover/Top Stories placements — tunes the selector.

## Publish-stage sequence (final form)

```
:45 publish → site live
:45+10s  news-sitemap.xml regenerated · RSS updated
:45+20s  IndexNow ping (existing key)
:45+30s  OG card rendered → Bluesky + Telegram + Mastodon posts (no X)
:45+60s  ledger row gains: distribution status per channel
daily    GSC sitemaps.submit · digest email (human-gated) · outreach drafts (human-gated)
weekly   pruning sweep · channel-performance report
```
