# UX 직관화 검토 — 공통 가이드 (병렬 에이전트용)

> 목표: 네비게이션이 완성된 my_room 스위트를 *사용자의 경험·눈동자·클릭* 중심으로 다시 본다. **디자인을 먼저 직관적으로** 고치고, 백엔드/로직/데이터 변경이 필요한 것은 *직접 하지 말고 기록·표기*만 한다(추후 일괄 조율). 작성 2026-06-26.

---

## 1. 검토 4 렌즈 (모든 페이지·버튼·섹션에 적용)

1. **경험 흐름** — 이 화면에 들어온 사용자가 *지금 뭘 하면 되는지* 3초 안에 아는가? 주 행동(primary action) 하나가 즉시 보이나? 다음 행동으로 자연스레 이어지나?
2. **눈동자(시각 위계)** — 가장 중요한 숫자/상태(정전가·WWI·NAV·가치뱃지)가 위계 최상단인가? 색은 *의미*(6이유 정본)만 쓰고 장식 색은 없나? 스캔 가능한가(F/Z 패턴)? 시선이 헤매는 곳은?
3. **클릭 최소화** — N클릭 행동을 1클릭으로? *인라인*(별점·담기·공개토글을 그 자리에서, 모달/인스펙터 경유 없이) · hover-reveal · **스마트 기본값**(인스펙터 기본 선택, 정렬 기본값) · 일괄 작업 · 키보드(⌘K 외).
4. **직관성(least astonishment)** — 버튼이 버튼처럼 보이나(affordance)? 라벨이 자명한가? 결과가 예측되나? 같은 행동은 같은 패턴인가?

추가 점검: **빈/콜드 상태**(도움되는 안내, NaN 0), **군더더기 제거**(중복 컨트롤·과한 텍스트 통합), **모바일/좁은 폭**.

---

## 2. 직접 고치는 것 vs 표기만 하는 것 (충돌 방지의 핵심)

**직접 고친다 (page-local, 자유):** 그 페이지의 main/inspector/activity 콘텐츠, 버튼 배치·라벨·affordance, 섹션 순서·시각 위계, 인라인 액션, 기본값, hover, 빈 상태, 페이지 내 카피.

**직접 고치지 말고 `[⚠ COORD]`로 기록만 한다 (공유 — 추후 일괄 조율):**
- 공유 **셸**: appbar/breadcrumb 패턴, 좌 레일 글로벌 네비 목록·아이콘, 인스펙터/활동 패널의 *틀*, `:root` 색 토큰, ⌘K 팔레트 `PAGES`.
- 공유 **어휘·표기**: 정전가/Standing·WWI·NAV·레벨·Discovery 명칭, **6+가용 이유 색**, **가치뱃지 수식**(gap=rating_pct−prestige, find≥+12/over≤−9), 별점 0.5–5 스케일.
- **백엔드/로직/데이터** 변경이 전제되는 개선(새 RPC·새 컬럼·새 집계·정렬 알고리즘 변경 등).

→ 공유 요소를 *건드려야* 더 직관적이라면, 페이지에선 손대지 말고 체인지로그 §3에 `[⚠ COORD: 대상]`으로 제안만 적는다. (예: "별점 인라인 입력이 모든 페이지에 필요 → 공유 별점 컴포넌트 `[⚠ COORD: 셸/별점]`".)

## 4. 작업 규약 (모든 에이전트 공통)

- 대상 파일 1개만 수정. 수정 전 **백업**: `cp .../mockup-me-<x>.html .../mockup-archive/mockup-me-<x>-preux.html`.
- 공유 셸(appbar/rail/inspector/activity/palette/tokens/JS)은 **보존** — 위 §2의 page-local만 직접 손댄다.
- 수정 후 **검증**: `<div>` open==close + `<script>` `node --check`. 깨지면 고치고 마무리.
- 체인지로그 `docs/ux/<page>.md` 필수. `[⚠ COORD]`는 눈에 띄게.
- 한국어 UI, 다크 운영 미감(공개 프로필만 라이트) 유지.
