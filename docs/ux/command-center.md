# UX 검토 · 커맨드센터 (`mockup-me-command-center.html`)

## 0. 한 줄 진단
이 페이지는 "지금 당신의 영화 자산(NAV) 현황 + 다음에 볼 한 편의 알파"를 약속한다.
가장 큰 마찰 두 개: (1) **들어오면 뭘 하면 되는지가 즉시 안 보임** — 주 행동(오늘의 추천 1편 담기/보기)이 스크롤 아래 추천 데스크의, 다시 인스펙터 안에 묻혀 있었다(2~3클릭). (2) 모듈이 길게 쌓여(hero→KPI→커버리지→추천→별자리) **위계가 평평** — 권위 매트릭스가 행동(추천)보다 위에 와서 시선이 "할 일"보다 "현황 점검"에 먼저 묶였다.

## 1. 렌즈별 발견 (경험·눈·클릭·직관)
- **경험 흐름**: hero(NAV)는 "내가 어디 서 있나"를 잘 답하지만 "그래서 지금 뭘?"의 답이 없었다. 추천 1위(Touki Bouki)는 인스펙터 기본 선택까지는 똑똑했으나, *행동 버튼*이 우측 인스펙터에만 있어 본문만 봐선 발견 불가.
- **눈동자**: 색은 6이유 정본만 사용(장식 색 없음) — 양호. 다만 커버리지 매트릭스가 추천보다 먼저 나와, 가장 "행동가능한" 모듈인 추천 데스크가 시각 위계에서 밀렸다. 매트릭스 헤더의 `aw` 약어가 자명하지 않았다.
- **클릭**: 추천/커버리지 행 → 인스펙터(좋음). 그러나 "담기/봤어요"가 인스펙터 경유라 **스캔→행 클릭→버튼**의 3스텝. 커버리지의 `관람순/facet` 세그먼트 버튼은 클릭돼 보이나 죽어 있었다(놀람). cold-start 데모 토글이 far-right 패널 최하단에 라벨 없이 묻혀 *발견 불가*.
- **직관성**: 추천 행이 클릭 가능해 보이는 신호가 약함(hover 시 "이게 분석을 연다"는 단서 부재). 칩(이유 뱃지)은 뱃지로 읽혀야 맞고 버튼처럼 오인되지 않음 — 유지.

## 2. 적용한 개선 (HTML 직접 수정)
- **"오늘 할 일" 액션 배너 신설 (hero 바로 아래)** → 들어오자마자 주 행동을 1순위로. [무엇] 추천 1위(Touki Bouki) 요약 + `[볼 영화에 담기]`(pri) / `[추천 자세히]` + 미니 바로가기 3개(라틴 블라인드 0% · S&S 완파 9편 · 추천 5편 대기, 각각 해당 모듈로 점프+인스펙터 선택). [왜] "현황만 보고 나가는" 대시보드를 "한 편 정하고 나가는" 대시보드로. [효과] 주 행동 0스크롤·1클릭, 다음 행동(블라인드/완파)도 1클릭 점프.
- **추천 데스크를 커버리지 매트릭스 위로 이동** (rail "이 화면" 순서도 동기화) → [왜] 가장 행동가능한 모듈을 위계 최상단으로(F패턴 첫 시선). [효과] 스크롤 없이 "다음 한 편" 후보 5개가 먼저 보임.
- **추천 행 인라인 퀵액션 (hover-reveal `[담기]`/`[봤어요]`)** → [무엇] 행 hover 시 우측에 인라인 버튼 등장(클릭은 행 선택과 충돌 않게 stopPropagation), 담기 시 토스트+행 dimming+버튼 "담김" 잠금. [왜] 인스펙터 왕복 제거. [효과] 담기 3클릭→**1클릭(hover+클릭)**, 인스펙터 안 열어도 됨.
- **추천 행 hover 단서 추가** → hover 시 "분석 ▸" 미세 라벨로 "행을 누르면 분석이 열린다"를 명시. [효과] affordance 명료화(놀람 제거).
- **cold-start 데모 토글 발견성 강화** → 점선 박스 + 「콜드스타트 데모 · 신규 가입(7편) 화면 미리보기」 라벨/힌트 부여. [왜] 시연용 핵심 토글이 묻혀 있었음. [효과] 무엇을 하는 스위치인지 라벨만으로 자명.
- **죽은 컨트롤 정직화 + 라벨 자명화** → 커버리지 `등급순/관람순/facet` 세그먼트에 `covSort()`(시각 토글) 연결로 "눌리는" 피드백 부여; 헤더 약어 `aw`→`관람%`로 교체; Abraccine(0%) 행에 `블라인드` 칩 추가해 본문에서도 블라인드가 보이게. [효과] 놀람 제거, 스캔성↑.

## 3. 조율 필요 (cross-page) — [⚠ COORD] 항목만
- **[⚠ COORD: 셸/별점·인라인 액션]** 인라인 "담기/봤어요"는 지금 페이지-로컬 토스트·DOM 표시(목업)다. *모든 페이지에서 동일하게 동작하려면* 공유 별점/담기 컴포넌트 + 상태 영속(watchlist/seen)이 필요 → 셸 레벨 공용 컴포넌트로 승격 제안. 영향: watchlist, collection-list, onboard-rate, asset-desk.
- **[⚠ COORD: 백엔드/정렬]** 커버리지 `관람순/facet`는 현재 시각 토글만(실제 재정렬 없음). 실제 정렬은 데이터 정렬 로직(RPC/클라 정렬)이 전제 → 일괄 조율 대상. 영향: analysis, asset-desk(동일 매트릭스 재사용 시).
- **[⚠ COORD: 어휘]** "오늘의 한 편 · 가장 큰 알파"/"오늘 할 일" 카피를 다른 진입 화면(watchlist 등)과 통일할지 검토 — 동일 추천 1위를 두 화면이 다르게 부르면 혼란. 영향: watchlist, onboard.
- **[⚠ COORD: 어휘]** 본문 매트릭스에 추가한 `블라인드` 칩 색=conquer(red). 블라인드 표기의 *정본 색/라벨*이 셸 어휘에 고정돼야 일관 — 확정 시 그 토큰으로 교체. 영향: 전 페이지 블라인드 표기.

## 4. 추후 로직·데이터 변경 제안 (지금 미적용)
- "담기/봤어요" 후 추천 리스트 자동 재계산(WWI 재정렬·다음 1위 승격) — recommend() 재호출 필요.
- "봤어요"가 평가 플로우(onboard-rate)로 자연 연결되는 핸드오프(상태 전달) — 라우팅/상태 설계 필요.
- cold-start 토글을 실제 사용자 상태(보유 편수<8)와 연동해 자동 표시.
