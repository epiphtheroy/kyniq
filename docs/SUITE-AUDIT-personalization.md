## 2. 발견한 비일관성 (전체를 미리 알았다면)

순차로 만들다 보니, 같은 개념이 페이지마다 다른 이름·축·색으로 굳었다. 다섯 가지가 핵심이다.

### 2.1 ★ 추천 "이유"의 축이 페이지마다 다르다 (가장 큰 문제)
하나의 영화가 "왜 추천/평가되는가"의 분해 체계가 3종으로 갈렸다:

| 페이지 | 쓰는 축 |
|---|---|
| command-center | **Affinity · Lineage · Gap-fill · Canon** (4) — WWI 서브점수 |
| asset-desk | **안전자산 · 안전한 모험 · 리니지 완파 · 구독 가용 · Reading** (5 전략) |
| watchlist | **안전자산 · 새로운 도전 · 도장깨기 · 공백 충족 · Reading · 정전 위상 · 구독 가용** (7 이유) |
| collection-list-v2 | 안전자산 · 안전한 모험 · 리니지 완파 (3 추천 칼럼) |

→ 같은 것을 Affinity=안전자산, Gap=공백, Canon=정전 위상으로 다르게 부른다. **단일 taxonomy 필요.**

### 2.2 포트폴리오 "총점/레벨"이 둘이다
- command-center: **Cinephile Index 648 / 1000 · Established**
- asset-desk: **NAV 1,284**

같은 "내 자산 수준"을 두 숫자가 경쟁한다. **하나로 통일.**

### 2.3 영화 1편의 "점수" 명칭이 갈린다
- 보유작: **정전가**(collection-list) · P/D
- 후보: **WWI**(watchlist) · 발굴
- command-center/desk: P · D · Δindex · 확신

→ *정전가(시장가치)* vs *WWI(나에 대한 적합도)* 는 본래 **다른 두 값**이라 분리 자체는 옳다. 다만 **명칭·분해축을 통일**하고 둘의 관계를 명시해야 한다.

### 2.4 글로벌 네비게이션이 페이지마다 제각각 (profile은 아예 없음)
실제 상단 `.tabs` 가 전부 다르고 불완전하다:

```
command-center : 커맨드·커버리지·추천 엔진·별자리·포트폴리오·공개   ← 이건 '페이지 내 섹션'을 탭처럼 오용
asset-desk     : 커맨드·자산 데스크·커버리지·완파·공개
analysis(-v2)  : 커맨드·자산 데스크·자산 분석·(해석 렌즈)·공개
collection-list: 커맨드·자산 데스크·자산 분석·보유 리스트
onboard(-v2)   : 기록·보유 리스트·자산 분석
library        : 기록·보유 리스트·서재·분석
write          : 서재·노트·보유 리스트
pair           : 서재·노트·동행
watchlist      : 자산 데스크·자산 분석·보유 리스트·볼 영화
profile        : (없음)
```

→ **단일 글로벌 네비**가 모든 페이지에 동일하게 있어야 한다.

### 2.5 버전 중복 / 기능 회귀
- `collection-list v2`는 v1의 상위집합(3단) → v1 은퇴.
- `onboard-rate v2`는 v1의 상위집합(리니지 칼럼) → v1 은퇴.
- **`analysis-v2`는 v1을 대체한 게 아니라 v1의 핵심(트로프·Reading·형상 렌즈 탐색·형상 클라우드·자기 서사)을 빠뜨렸다.** 당신은 *둘 다*를 원했음(리니지 메인 + 렌즈) → **하나로 병합**해야 한다.
- `command-center`(현황)와 `asset-desk`(운용)는 사실상 같은 "내 자산 허브"의 두 면 → 관계 정리 필요(§3).

## 3. 표준화 제안 (개선)

### 3.1 단일 추천-이유 taxonomy (전 페이지 공통)
6개로 고정하고, 색·아이콘·정의를 한 곳에서 관리(`lib/recReasons.ts` 가정):

| 이유 | 친근 명 | 색 | 정의 | command-center 대응 |
|---|---|---|---|---|
| `safe` 안전자산 | 검증된 감동의 연장 | teal `#1FB286` | 고친연도·저분산 | Affinity |
| `frontier` 안전한 모험 | 새로운 도전 | blue `#3E8FE0` | 신영역 + 정전 안전망 | (신규) |
| `conquer` 리니지 완파 | 도장깨기 | red `#E3120B` | 감독·정전 완성 진척 | Lineage(일부) |
| `gap` 공백 충족 | — | amber `#C8922B` | 내 sparse 축 메움 | Gap-fill |
| `canon` 정전 위상 | — | gold `#D9A441` | S&S·수상 standing | Canon |
| `reading` Reading | — | violet `#9B8CF0` | 내가 반응하는 오독 렌즈 | (신규) |
| (`avail` 구독 가용) | — | green `#2E9E5B` | *이유가 아니라 필터/가산* | (신규) |

> `avail`(구독 가용)은 점수 이유가 아니라 **취득 가능성** → 별도 신호(필터·가산·만료경고)로만. watchlist 색이 이미 이 표와 일치 → **watchlist를 색·축의 정본으로 채택.**

### 3.2 단일 점수·레벨 어휘
- **영화적 자산 NAV** = 유일한 포트폴리오 총량(누적 가치). `Cinephile Index 648`는 *레벨 밴드*로 흡수 → 헤더엔 "NAV 1,284 · LV. Established(상위 14%)" 한 줄.
- **정전가(Standing)** = 영화의 *시장 가치* = 계보층 PrestigeScore(+γ·Discovery). 보유작·후보 공통으로 표기.
- **WWI(Why-Watch Index)** = 후보의 *나에 대한 적합도* = §3.1 이유들의 가중합. 후보에만.
- 보유작 카드의 **가치 뱃지**(저평가 발굴/정전 합치/고평가)는 `정전가 vs 내 별점` 그대로 유지 — 좋은 고유 지표.

### 3.3 단일 글로벌 네비
모든 페이지 상단 동일. 사적(다크) 영역 안에서:

```
[기록] [내 자산 ▾] [볼 영화] [서재] [노트] [동행]            … [공개 프로필 ↗]
        └ 커맨드(현황) · 운용 데스크 · 분석
```

- **내 자산** 드롭다운으로 command-center(현황)·asset-desk(운용)·analysis(분석)를 묶는다. 페이지 *내부* 섹션 이동(커버리지·별자리 등)은 네비가 아니라 본문 앵커/탭으로 분리.
- profile은 "공개 ↗"로 라이트 영역으로 넘어감을 표시.

### 3.4 버전·중복 정리
| 조치 | 대상 |

| v1 은퇴(아카이브) | `collection-list`, `onboard-rate` |

## 4. 교차링크 지도 (연결 조직 — "한꺼번에 합칠 때")

페이지를 잇는 의도된 동선. 지금은 각자 섬이라 이 배선이 비어 있다.

```
onboard(평가) ──본 영화──▶ 보유 리스트 ──드릴다운──▶ 분석(그 영화의 렌즈)
     │                           │ 저평가 발굴 ──▶ 공개 프로필 하이라이트
     └──담기──▶ 볼 영화(watchlist)
분석: 블라인드/공백 ──필터 점프──▶ 볼 영화(그 공백 후보)
분석: 감독 상호추천/affinity ──▶ 볼 영화 후보(이유=안전자산/공백)
내 자산 데스크: 추천 "+워치리스트" ──▶ 볼 영화(이유 보존)
볼 영화: "봤어요" ──별점 요청──▶ 보유 리스트(승격) │ 순위 ──▶ 오늘 볼 것
서재: 공개 컬렉션 ──▶ 프로필 모듈   │ 노트: 공개 글 ──▶ 프로필 모듈
영화/형상 페이지 ──강한 오독 작성──▶ 노트 ──(공개)──▶ 영화 코멘트 / 형상 미스리딩
이중 노출: 간직 ──▶ 서재  │ 건넨 한 편 ──▶ 볼 영화(담기)
```

공통 척추 = **`user_films.status`(본 영화/볼 영화)** + **`user_pins`(다형 담기)** + **`takes`(노트/오독)** + **`user_rank`(순위)**. 모든 페이지가 이 4개를 읽고 쓴다(스키마는 `docs/PLAN-personalization-portfolio.md` 확장).
