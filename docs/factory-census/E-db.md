## 4. Key hazards for the importer factory
1. ⚠️ `films.visible` trigger (≥3 approved figures) is **live-only, unversioned** — capture before automating (RUNBOOK §6D).
2. ⚠️ Corpus-wide stages (embed→consolidate→author/rank/recommend→trope-build→SEO) can **rename/re-link live entities**; incremental-additive path exists only for tropes (`worker/trope-incremental.py` + `trope_match_takes` RPC, threshold 0.72). `trope-build --reset` wipes ALL trope hubs; `mt-recluster`/`mt-dedupe-rename` null `seo_phrase`; redirects depend on `merged_into` + `slug_history`.
3. ⚠️ Ordering: TMDB fetch before extract; bold-take/asset loads before embed; SEO after any rename; embed before consolidate/rank/tropes.
4. ⚠️ PostgREST 1000-row cap on every REST/RPC table response — jsonb_agg single-row pattern is the standard bypass; big room lists need `.range()` + deterministic tiebreakers.
5. ⚠️ Anon 3s statement_timeout wall — any new anon RPC needs a function-level `set statement_timeout`.
6. ⚠️ `compute_film_scores` = global delete + needs lineage — forbidden as a casual refresh.
7. ⚠️ Signature changes to overloaded fns require DROP-first + re-GRANT (surprise, screener, film_sentences_for, map_film_overview 0-arg legacy overload).
8. ⚠️ New search `kind` = RPC + frontend `hrefOf` in the same deploy.
9. ⚠️ `lib/slug.ts` is the ONLY slug generator (post-0039); the old diacritic-dropping slugify in `app/api/admin/films/import/route.ts` caused the director dedup surgery.
10. ⚠️ pgvector HNSW: build partial (published) indexes only.
11. `content_i18n` (autonomous translation reconciler, i18n master plan) — **not yet in repo SQL**; planned table keyed by source_sha256. VERIFY live status before designing around it.
