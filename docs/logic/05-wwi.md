# 코어 엔진 ⑤ — WWI (Why-Watch Index) · 추천 이유 엔진

*개인화 로직 명세 시리즈 5/8. 작성 2026-06-26. 짝: `docs/logic/01-taste-vector.md`(취향), `docs/logic/02-standing.md`(정전가), `HANDOFF-MASTER-personalization.md`(전체), `docs/SUITE-AUDIT-personalization.md`(★어휘·이유 색 정본), `handoff/07_scoring_model.md`(점수 모델), `docs/PLAN-personalization-portfolio.md`(WWI 초안 §4.2). 입력 목업: `mockup-me-watchlist.html`·`mockup-me-asset-desk.html`·`mockup-me-collection-list-v2.html`. 마지막에 8개를 합쳐 단일 로직 명세로 묶는다.*

> **이 엔진은 시리즈에서 가장 중요한 상위 엔진이다.** 다른 엔진(①②③④⑥⑦)이 *재료*를 만들면, WWI는 그것을 **"왜 이 영화를 봐야 하는가"라는 하나의 결정**으로 통합한다. 추천이 일어나는 세 면 — 볼 영화(파이프라인)·운용 데스크·보유 리스트 추천 — 의 *심장*이 전부 이 엔진이다.

---

## 1. 우리가 하려는 것 (처음 듣는 사람을 위해)

**한 문장:** 한 후보 영화가 *나에게* 얼마나 볼 가치가 있는가를 — 단일 점수가 아니라 **여러 "이유"로 분해된 가중합**으로 — 매기고, 그 이유들을 *기여도 순으로 펼쳐* 설명하는 엔진.

자산운용 비유로 옮기면 이렇다. 영화는 자산이고, 한 사람의 유한한 관람 생애는 자본이다. 그 자본을 한 편에 투입할지 말지는 **애널리스트의 BUY 리포트** 같은 판단을 요한다. 그런데 좋은 리포트는 "이 종목 좋습니다" 한 줄이 아니다. *왜* 좋은지 — 저평가라서? 신흥시장 분산이라서? 내 포트폴리오의 빈 섹터를 메워서? — 를 **논거별로 분해**하고, 가장 무거운 논거를 위에 둔다. WWI가 하는 일이 정확히 그것이다.

**왜 "단일 점수"가 아니라 "이유의 합"인가 — 이게 설계의 전부다.** Letterboxd식 추천은 "당신과 비슷한 사람들이 좋아함" 하나로 끝난다. 블랙박스다. MetaTake의 가치는 *유한 자본을 쓰는 결정에 납득 가능한 논거를 주는 것*이다. 그래서 WWI는 **6개의 이유**(safe·frontier·conquer·gap·canon·reading)로 후보를 동시에 평가하고, 각 이유의 기여를 합쳐 종합 점수를 만들되, **분해를 절대 버리지 않는다.** 사용자가 보는 것은 "WWI 88"이 아니라 "WWI 88 — *왜냐하면* 브레송 도장깨기 1편 남음(+32), 9★ 군집 직속(+28), 정전(+14), Criterion 상시(+12)"다.

**엔진 ⑤의 자리.** ①(취향)·②(정전가)가 *두 축*(주관·객관)이라면, WWI는 그 둘을 포함한 **여섯 신호를 가중 결합하는 상위 통합기**다. ①의 `v_loved`는 safe가 되고, ②의 standing은 canon이 되며, ④(공백)은 gap, ⑦(커버리지)은 conquer가 된다. **WWI는 새 데이터를 만들지 않는다 — 다른 엔진의 출력을 *결정으로 합성*한다.** 이게 "상위 엔진"의 정의다.

## 2. 목표 산출물 (사용자 경험 중심)

WWI는 추천이 일어나는 **세 면 전부**에 같은 엔진으로 연료를 댄다. 세 면은 *같은 후보별 산출물*을 다른 밀도로 소비한다.

### 2.1 볼 영화 (파이프라인 · `mockup-me-watchlist.html`)
가장 *풀 스택* 표면. 후보 카드마다:

| 사용자가 보는 것 | WWI에서 어떻게 나오나 |
|---|---|
| **WWI 88** (종합, 85+면 빨강 강조) | 6개 이유 기여의 가중합, 0–100 정규화 |
| **"왜 추천되었나 · 기여도 순"** 이유 스택 | 후보의 reasons[]를 `c` 내림차순으로 펼침 (설명가능성의 핵심) |
| 각 이유 행: **색 칩 + 한 줄 사유 + 지표 + 기여바** | `{ty, tx, m, c}` — 예: `frontier · "가장 먼 신대륙 — 세네갈, 정전 안전망" · 발굴 94 · ▓▓▓` |
| **발굴 점수**(Discovery) 보조 표기 | frontier/canon 입력의 ②Discovery |
| **만료 D-5** 경고, 채널 칩 | avail(이유 아님 — 가용성 필터/가산/만료) |
| **순위 1·2·3 podium**, "짧은 밤(러닝타임)" 정렬 | WWI ∩ 가용 ∩ 짧은 러닝타임 = "오늘 밤 볼 것"(§4-h) |

### 2.2 운용 데스크 (`mockup-me-asset-desk.html`)
*애널리스트 데스크* 톤. 같은 후보를 **5전략 + 확신도 + E/R**로 본다.

| 사용자가 보는 것 | WWI에서 |
|---|---|
| **확신도(논거 수) 순** 추천 리스트 | conviction = 한 후보가 가진 *유효 이유 개수*(§4-d) |
| **확신 ●●●○** (4점 만점 점) + "확신 3" | conviction 시각화 |
| 한 종목의 **다중 전략 태그** — "완파·브레송 1편 남음 / 안전자산·9+ 군집 / 구독 가용" | 그 후보의 상위 이유들을 *전략명*으로 노출 |
| **Δindex +5** (한계 기여) | 이 한 편을 보면 NAV가 몇 점 오르나(§4-e, 엔진⑧ 연결) |
| **E**(기대 미적수익) **/ R**(리스크=실망 확률) | E = WWI 또는 safe·canon 기반 기대치, R = 분산·신뢰도 기반(§4-e) |
| **리스크–리턴 프론티어** 산점도 | 후보들을 (R, E) 평면에 — 안전자산=좌상, 모험=우측이되 닻이 하방 받침 |

### 2.3 보유 리스트 추천 (`mockup-me-collection-list-v2.html`)
보유작 1편을 고르면 **3전략 추천 광고카드**가 뜬다(닮은 후보를 판다).

| 칼럼 | WWI 이유 |
|---|---|
| **안전자산**(검증된 감동의 연장) | safe — 그 영화 군집과 친연도 높은 후보 |
| **안전한 모험**(미답 영역 + 안전망) | frontier — 새 영역이되 공유 정전이 하방 받침 |
| **리니지 완파**(도장깨기 · 계보를 끝까지) | conquer — 같은 감독/정전 라인의 잔여 |

→ **시스템이 저장하는 것**: 후보 1편당 `{wwi, reasons[](정렬됨), conviction, delta, discovery, avail[]}`. **`reasons[]`(분해)가 없으면 WWI는 출시 금지** — 설명 불가능 = 금지(`07` 원칙, ① 앵커 원칙과 동일).

**경험 품질의 기준:** "WWI 88"만 보이면 실패다. "*왜* 88인지"가 한 줄로 납득되면 성공. 그 차이는 *reasons[]를 기여도 순으로 펼쳤는가*에서 갈린다.

## 3. 활용 가능한 데이터 (= 다른 엔진의 출력)

WWI는 원시 DB를 거의 안 본다. **입력의 대부분이 다른 엔진의 산출물**이다. 그게 상위 엔진의 본성이다.

| 이유 | 입력 엔진/데이터 | 위치 | 신호 강도 |
|---|---|---|---|
| **safe**(친연도) | ① `v_loved` ↔ 후보 `v_film` 코사인 (clusters면 max-cluster) | `user_taste_profile`, `film_vectors` | ★★★★★ |
| **frontier**(새로운 도전) | ① `v_watched` 앵커 분포(미답 국가/사조) + ② standing/Discovery(안전망) | ①·② 출력 | ★★★★ |
| **conquer**(도장깨기) | ⑦ 커버리지(라인 진척률) + 감독/정전 잔여 편수 | `film_lineage`, ⑦ 출력 | ★★★★ |
| **gap**(공백 충족) | ④ 공백/희소 출력(후보가 sparse 축을 메우는 정도) | ④ 출력 | ★★★ |
| **canon**(정전 위상) | ② `prestige/total`(또는 백분위) | `film_scores` | ★★★★ |
| **reading**(Reading) | 내 framework 성향 분포 ↔ 후보 framework 강도 | `takes.framework`, ① 앵커 | ★★★ |
| **avail**(구독 가용·*이유 아님*) | 스트리밍 조인 + 만료일 | 가용성 테이블/외부 | (필터/가산) |
| 메타 | 후보 러닝타임(오늘 밤), 트랙 | `films` | ★ |
| 신뢰도 | ① confidence, N_loved | `user_taste_profile` | ★★★(폴백 결정) |

핵심: **WWI의 품질은 곧 입력 엔진들의 품질**이다. 그래서 ①의 confidence가 낮으면(콜드스타트) WWI는 safe/gap을 *신뢰하지 않고* canon으로 폴백한다(§4-g). 입력이 거짓말하면 WWI도 거짓말한다 — 그래서 신뢰도가 1급 입력이다.

## 4. 본질적 문제 · 설계 주의점 · 방향성

여기가 설계의 심장이다. 9개 결정 지점, 각각 *문제 → 권장 방향*. (요청 §4 (a)–(i)에 대응.)

### (a) 이유별 가중치 default와 정규화 (0–100)
6개 이유를 *어떻게 합치나*. 각 이유의 하위 산출은 스케일이 제각각(코사인 0–1, 순위, 편수, 백분위)이라 그대로 더하면 한 이유가 점수를 삼킨다.

- **방향 — 두 단계.** ① 각 이유를 *그 이유 안에서* 0–100으로 정규화(`s_safe, s_frontier, …`). 코사인은 `100·(cos−lo)/(hi−lo)` 같은 캘리브레이션, conquer는 진척률, canon은 standing 백분위. ② 그 다음 **가중합**:
  ```
  WWI = clamp01..100( Σ_r w_r · s_r ) / Σ w_r        (r ∈ {safe,frontier,conquer,gap,canon,reading})
  ```
- **default 가중치(가설):** `w_safe 0.30 · w_frontier 0.18 · w_conquer 0.15 · w_gap 0.15 · w_canon 0.12 · w_reading 0.10`. 합 1.0. safe가 최대 — *섬뜩하게 맞는* 친연도가 추천의 1차 동력. 단 §4-f의 다양성 바닥이 safe 독식을 막는다.
- **이유 하위 산출(각 0–100):**
  - `s_safe   = norm( cos(v_loved, v_film) )`  — clusters 있으면 `max_k cos(c_k, v_film)`(밍밍함 회피, ①-d).
  - `s_frontier = 신영역도 × 안전망`(아래 (b)에서 수식화).
  - `s_conquer = 진척 surface`(아래 (c)).
  - `s_gap    = ④ 출력` (이미 0–100로 받음).
  - `s_canon  = ② standing 백분위` (또는 `total/최대`).
  - `s_reading = align(내 framework 분포, 후보 framework 강도)`(아래 (i)).
- **상수는 전부 가설.** 형태(2단 정규화+가중합)를 고정하고, 가중치·캘리브레이션 lo/hi는 실데이터 백분위로 튜닝(§6).

#### (b) frontier 수식화 — 상방 큼·하방 제한 (가장 미묘)
"안전한 모험"의 본질은 **비대칭 페이오프**: 미답 영역이라 *상방이 크고*(새 대륙·새 사조), 공유 정전·신뢰 감독이라 *하방이 제한된다*. 단순 곱이면 둘 중 하나가 0일 때 죽는다 — 그런데 *안전망 없는 순수 모험*은 frontier가 아니라 risk다(추천 안 함), *모험성 없는 정전*은 그냥 canon이다.

- **방향 — 곱셈 게이트 + 안전망 바닥:**
  ```
  novelty(f) = 1 − 내가 이 영역(국가·사조)에 가진 노출 비율        # 미답일수록 1
  net(f)     = max( s_canon(f)/100 , dir_anchor(f) )              # 정전 OR 신뢰 감독 닻
  s_frontier = 100 · novelty(f) · ( θ + (1−θ)·net(f) )            # θ≈0.25 = 안전망 바닥
  ```
  - `novelty=0`(이미 가본 영역)이면 frontier 0 — 모험이 아님.
  - `net=0`(정전·닻 전무)이면 `s_frontier = 100·novelty·θ` — *바닥 θ만 남아* 추천이 약해진다(하방 무제한 = 억제). 운용 데스크 카피 "신대륙이되 양더창의 닻에 묶인 모험 — 상방 큼, 하방 제한"이 정확히 이 구조.
  - `dir_anchor` = 후보 감독이 내 *신뢰 감독*(고평점·다편 본)인지(0–1). 양더창처럼.
- **avail(무비용)은 frontier 점수에 *안 들어간다*** — 가용성은 이유가 아니다(§4 avail). 단 표시에선 "정전 + 무비용"으로 묶여 보일 수 있음.

#### (c) conquer 수식화 — 어느 라인의 완성을 surface하나
도장깨기는 ⑦ 커버리지·정전 완성 진척이다. 문제: 한 후보는 *여러 라인*(감독 필모, 칸 팔메 컬렉션, S&S 250, 금마장…)에 동시에 속한다. 전부 보여주면 노이즈고, 평균 내면 *임박한 완파*의 짜릿함이 죽는다.

- **방향 — "가장 임박한 한 라인"을 surface(max, not mean):**
  ```
  진척(L) = 내가 본 L 멤버 / |L|                                  # 0–1
  임박도(L) = 진척(L) · authority(L) · 잔여보너스(잔여 ≤ 2면 ↑)
  s_conquer = 100 · max_L( 진척(L) · g(잔여_L) )                  # 후보가 +1 하는 라인 중 최댓값
  ```
  - `g(잔여)`는 잔여가 적을수록 급증: 잔여 1편 = "브레송 5/6 → 1편 남음!"이 **최강 카피**. watchlist의 `conquer "브레송 도장깨기 — 1편 남음! · 5/6 · c32"`가 이 max를 surface한 결과.
  - surface 우선순위: **(잔여 1–2편 거장 필모) > (높은 권위 정전 라인) > (국가 정전)**. 사용자가 *끝을 볼 수 있는* 라인을 위에.
  - 표시 지표 `m`은 진척 분수("5/6", "8%", "2편째") — 진척 자체가 동기.

### (d) 개인화 슬라이더 (Affinity ↔ Discovery 틸트)
default 가중치는 *평균 시네필*용. 어떤 날은 "익숙한 걸 보고 싶다", 어떤 날은 "모험하고 싶다". 가중치를 사용자가 *한 손잡이*로 기울일 수 있어야 한다(블룸버그 팩터 틸트).

- **방향 — 단일 슬라이더 `t ∈ [−1, +1]`** (좌=Affinity, 우=Discovery):
  ```
  safe·canon 가중  ×= (1 − β·t)         # Discovery로 갈수록 ↓
  frontier·gap 가중 ×= (1 + β·t)        # Discovery로 갈수록 ↑
  conquer·reading   고정(중립 축)
  (β≈0.6, t=0이 default)
  ```
  - 한 슬라이더가 *두 그룹*을 반대로 민다 → "안전 ↔ 모험" 한 축으로 직관적.
  - 슬라이더는 *가중치만* 바꾼다 — 하위 산출 `s_r`은 불변. 그래서 같은 후보가 슬라이더에 따라 *재정렬*될 뿐, 점수가 거짓이 되진 않는다.
  - WWI는 항상 *현재 t*로 계산해 표시. 데스크는 t=0(중립 운용), 볼 영화는 사용자 슬라이더.

### (e) 이유 스택을 기여도 순으로 펼치기 (설명가능성 = 핵심)
**이 엔진의 존재 이유.** 종합 점수는 정렬·뱃지용이고, *사용자를 설득하는 것은 펼쳐진 이유*다.

- **방향:** 후보별로 각 이유의 **기여 `contrib_r = w_r · s_r`** 를 계산 → **내림차순 정렬** → 위에서부터 `{색, 친근명, 한 줄 사유 tx, 지표 m, 기여바 길이 ∝ contrib}` 로 렌더. watchlist의 `reasons:[{ty, tx, m, c}]`가 정확히 이 구조(`c`=기여).
  - **표시 컷:** 기여 상위 *유효 이유만*(예: contrib ≥ 임계 or 상위 4–5개). 0 기여 이유는 숨김(노이즈 제거).
  - **사유 문장 `tx`는 템플릿**: safe="당신 9★ 군집 직속", frontier="가장 먼 신대륙 — 세네갈, 정전 안전망", conquer="브레송 도장깨기 — 1편 남음!", gap="아프리카 정전 0% → 첫 진입", canon="S&S 2022 #66", reading="정치적 무의식 렌즈". 각 이유 엔진이 *근거 토큰*(앵커명·라인명·순위·진척)을 함께 내보내야 문장이 산다(② components, ⑦ 라인명과 동일 계약).
- **avail은 이유 스택 맨 아래** 별도 톤(green): "MUBI 만료 D-5" — *점수 이유가 아니라 취득 조건*임을 시각적으로 분리.

### (f) 확신도 (conviction) = 이유 개수
종합 점수가 같아도 *한 이유로 88*과 *네 이유로 88*은 다른 추천이다. 전자는 한 다리로 선 베팅, 후자는 *다중 논거의 합의*다. 애널리스트가 "복수 시그널이 BUY를 가리킨다"고 할 때의 확신.

- **방향:** `conviction = #( contrib_r ≥ τ )` — 유효 기여를 낸 이유의 *개수*(τ=기여 임계, 예 0–4점). 데스크의 "확신 ●●●○ / 확신 3"이 이것.
  - conviction은 WWI와 **독립 표시** — 정렬을 conviction 순(데스크)으로도, WWI 순(볼 영화)으로도 둘 다 제공.
  - 한 줄 다리(safe만 높음)는 conviction 낮음 → *과적합 의심* 신호로도 쓰임(§4-g와 연결): 콜드스타트일수록 conviction이 1(canon만)로 떨어진다.

### (g) Δindex (한계 기여) — 이 한 편이 NAV를 몇 점 올리나
운용 비유의 정점: 후보는 *점수*가 아니라 **포트폴리오에 추가될 때의 가치 증분**으로 평가돼야 한다. 같은 WWI라도 *내가 비어 있는 라인*을 메우면 NAV가 더 오른다(한계효용 체감의 반대 — 희소 축이 비싸다).

- **방향 — 엔진⑧(NAV)와의 계약:**
  ```
  Δindex(f) = NAV(보유 ∪ {f}) − NAV(보유)          # 한계 기여(엔진⑧가 계산)
  ```
  - WWI는 *내 적합도*(주관·소비 결정), Δindex는 *내 자산 총량에의 기여*(보유 후 가치). 둘은 **다른 질문** — 둘 다 표시(데스크 "Δindex +5/+6").
  - 근사(엔진⑧ 미연결 시): `Δindex ≈ a·standing_백분위 + b·희소도(gap) + c·완파보너스(conquer 잔여 1편)`. 희소·완파일수록 큼.
  - **WWI는 Δindex를 *직접 계산하지 않는다* — 엔진⑧에 후보를 넘기고 받아 표시한다.** 경계: WWI=적합도, ⑧=한계가치.

### (h) 필터버블 / 다양성 — 안전자산만 추천하면 갇힌다
safe 가중이 가장 크다(§4-a). 순진하게 정렬하면 *친연도 높은 것만* 상위에 깔려 사용자가 자기 취향의 감옥에 갇힌다(①-j 경고와 직결). MetaTake의 가치는 *취향 확장*도 포함한다.

- **방향 — 세 겹 방어:**
  1. **다양성 바닥(추천 구성 제약):** 상위 N 추천에 *frontier·gap 최소 비율*을 보장(예: top 12 중 ≥ 3은 frontier/gap 주도). 순수 점수 정렬이 아니라 *MMR식 재정렬*(이미 뽑힌 것과 닮으면 감점).
  2. **슬라이더 default 위치:** t=0이 *완전 safe가 아니라* 약한 균형. 사용자가 원하면 더 safe로.
  3. **경고 연동:** ①이 "취향이 한 군집에 쏠림"을 경고하면 WWI가 *그 면에서* frontier/gap 가중을 일시 상향("균형추 모드"). 자산운용의 *리밸런싱 권유*.
  - 한 줄 원칙: **safe는 추천의 1차 동력이되 독점자가 아니다.** frontier·gap이 균형추(①-j, ②-c의 Discovery와 같은 철학).

### (i) reading 수식화 + 콜드스타트 과적합 경고
**reading:** 내 *framework 성향*(14종 오독 렌즈)과 후보의 framework 강도의 정렬. 내 성향 = (내가 쓴 take의 framework 분포) + (높게 준 영화에 달린 take의 framework 분포)의 가중 혼합.
```
my_fw = normalize( λ·내가쓴_take_fw_분포 + (1−λ)·고평점영화_take_fw_분포 )   # λ≈0.6(내 글 우선, ①-k)
cand_fw = 후보에 달린 take의 framework 분포(강도 가중)
s_reading = 100 · cos(my_fw, cand_fw)
```
- watchlist 카피 "정신분석 ★ 당신 반응 축", "정치적 무의식 렌즈"가 이 정렬의 surface. 데스크 Reading 성향 패널(strong misreading)이 `my_fw`의 노출.
- thin content(후보에 take 없음)면 `cand_fw` 미정 → reading 가중 0으로 폴백(①-c thin content 처리와 동일).

**콜드스타트 과적합 경고(<10편이면 canon 폴백) — 필수.** N_loved가 적으면 `v_loved`가 노이즈 → safe·gap·reading이 *거짓으로 자신만만*해진다("3편 봤는데 친연도 96%"는 헛소리).
- **방향:** ① confidence를 받아 **신뢰 게이트:**
  ```
  if N_loved < N_min(가설 8~10):   # ①-e 임계와 동기
     w_safe, w_gap, w_reading ×= confidence    # 주관 이유를 신뢰도만큼 감쇠
     w_canon ↑ (폴백)                          # 객관 정전으로 무게 이동
     UI 라벨 "포트폴리오 형성 중 · 정전 위주 추천"
     conviction 표시에 신뢰 캡(≤2)
  ```
  - 즉 **데이터가 없으면 WWI는 ②(정전가)에 기댄다** — 모두에게 옳은 영화부터. 데이터가 쌓이며 주관 이유가 깨어난다. (PLAN §4.2 "보유분 적으면 Canon 위주, 과적합 경고"와 동일.)

### (h+) "오늘 밤 볼 것" = WWI ∩ 가용 ∩ 짧은 러닝타임
실제 행동을 부르는 좁은 추천. *지금 결정 가능한* 한 편.
- **방향:** `tonight = filter(가용=true ∧ 러닝타임 ≤ R_max) → sort by WWI → top 1–3`. watchlist의 "짧은 밤(러닝타임)" 정렬 + 가용 채널 + WWI를 교집합. podium(순위 1·2·3)이 이 결정의 고정 장치.
  - avail이 *필터*로 작동하는 대표 사례 — 점수엔 안 들어가지만 "오늘 밤"에선 *하드 게이트*.

### (i+) 보유작 가치 뱃지(정전가 vs 별점) ↔ WWI 관계 정리
혼동 주의: **보유작의 가치 뱃지와 후보의 WWI는 다른 엔진의 다른 질문**이다.
- **보유작(이미 봄):** `gap = 내별점×10 − 정전가` → 저평가 발굴(+12↑)/정전 합치/고평가 실망(−9↓). *과거 매수의 사후 평가*(②와 별점의 차익, ②-j). **WWI 아님.**
- **후보(아직 안 봄):** **WWI** = *나에 대한 적합도*(미래 매수의 사전 점수). canon 이유가 ②standing을 쓰므로 *입력은 공유*하지만 산출은 다르다.
- **방향:** UI에서 **명칭으로 분리** — 보유 리스트 카드 가격 자리 = "정전가 88", 후보 카드 = "WWI 88". 같은 88이어도 의미가 다름을 명시(SUITE-AUDIT §3.2 어휘 분리). 보유작에서 후보로 넘어가는 다리가 collection-list-v2의 3전략 추천(보유작 1편 → 닮은 후보들의 WWI 이유).

## 5. 권장 설계 (1차안 — 못박을 공식)

> 모든 상수는 *가설*. 실데이터로 캘리브레이션(§6). 핵심은 *형태*를 고정하는 것.

**이유 하위 산출(각 0–100):**
```
s_safe     = norm_cos( max_k cos(c_k, v_film(f)) )                    # ① clusters
s_frontier = 100 · novelty(f) · ( θ + (1−θ)·max(s_canon/100, dir_anchor(f)) )   # θ≈0.25
s_conquer  = 100 · max_L( 진척(L) · g(잔여_L) )                       # ⑦, g=잔여1편↑
s_gap      = ④.gapfill(f)                                            # 0–100 그대로
s_canon    = ②.standing_백분위(f)
s_reading  = 100 · cos(my_fw, cand_fw(f))         (cand_fw 없으면 가중 0)
```

**가중치(틸트 적용):**
```
w0 = {safe .30, frontier .18, conquer .15, gap .15, canon .12, reading .10}
tilt(t): safe,canon ×=(1−β·t) ; frontier,gap ×=(1+β·t) ; conquer,reading 고정   (β≈0.6)
콜드게이트(N_loved<N_min): safe,gap,reading ×= confidence ; canon ↑
```

**종합 · 분해 · 부산물:**
```
contrib_r = w_r · s_r
WWI(f)    = 100 · Σ_r contrib_r / Σ_r w_r                # 0–100
reasons[] = sort_desc_by(contrib_r) → [{ty, tx(템플릿), m(근거지표), c=contrib_r}]   # 표시 핵심
conviction= #( contrib_r ≥ τ )                          # 논거 수
Δindex(f) = 엔진⑧.marginal(보유, f)                      # 한계 NAV 기여(근사 가능)
avail[]   = 스트리밍 채널 + 만료D-day                     # 이유 아님: 필터/가산
discovery = ②.discovery(f)                              # 발굴 보조 표기
```

**다양성 재정렬(추천 면 구성 시):** 점수 정렬 후 **MMR** — `pick = argmax( λ·WWI − (1−λ)·max_sim(이미뽑힌것) )`, frontier/gap 최소 비율 바닥. (①이 쏠림 경고 시 frontier/gap 가중 일시 상향.)

**"오늘 밤":** `tonight = top3( sort_WWI( filter(avail ∧ runtime≤R_max) ) )`.

**저장(후보 단위, 캐시 `watchlist_scores` 또는 `score_watchlist(uid)` RPC 반환):**
```
user_id, film_id, wwi, reasons jsonb, conviction, delta, discovery,
avail jsonb, slider_t, confidence_at_calc, model_version, computed_at
```

## 6. 콜드스타트 · 캘리브레이션 · 갱신

- **콜드스타트(0–7편):** safe·gap·reading을 confidence로 감쇠, canon 폴백("형성 중 · 정전 위주"), conviction 캡 ≤2. *과적합 경고는 라벨로 정직히*(PLAN §4.2). → **데이터 없으면 WWI=②(모두에게 옳은 영화).**
- **8–30편:** 주관 이유(safe·gap·reading) 깨어남, frontier 의미 생김(노출 분포 신뢰), conviction 풀가동.
- **30편+:** 안정. 슬라이더 틸트·다양성 리밸런싱이 의미. drift(①-f)로 "취향 이동" 반영.
- **캘리브레이션(가설→실측):** ① 각 이유 정규화 lo/hi를 코퍼스 백분위로(s_safe 코사인 분포, canon 백분위 정합). ② default 가중치 `w0`를 파일럿 보유분으로 튜닝(PLAN §8-4: 35/30/20/15 초안은 *구 4축* — 본안은 6축 .30/.18/.15/.15/.12/.10로 갱신). ③ θ·β·τ·g(잔여)·N_min·R_max 튜닝. **검증:** "WWI 상위 ≈ 90+, 중앙값 ≈ 50", "9★ 군집 직속 후보가 top에 오나", "frontier가 미답 대륙을 올리나".
- **갱신:** ① 본 영화/평점 변경 → ①·④·⑦ 재계산 → WWI dirty. ② 가용성 변경(만료/신규)·슬라이더 이동은 *경량 재계산*(가중·필터만). ③ TTL(예 15분)+dirty, ① confidence 변동 시 폴백 라벨 재평가. `model_version` 불일치 시 전원 재계산(① 정책과 동일).

## 7. 다른 엔진과의 인터페이스 (이 엔진이 *내보내는* 것)

**입력(소비):** ① `{v_loved, clusters, anchors, confidence, N_loved}` · ② `{standing, discovery, total, components}` · ③ 리니지 관련성(닻 후보) · ④ `gapfill(f)` · ⑥ 유사도(MMR 다양성·보유작→닮은 후보) · ⑦ 라인 진척/잔여 · 가용성(스트리밍+만료) · `user_films`(보유 집합·러닝타임).

**출력(소비처):** 후보 1편당 단일 객체를 세 면이 다른 밀도로 소비.

| 소비처 | 쓰는 산출물 |
|---|---|
| 볼 영화(파이프라인) | `wwi` · `reasons[](정렬)` · `discovery` · `avail[]`(만료) · 러닝타임("오늘 밤") · 순위 |
| 운용 데스크 | `conviction`(정렬·●) · 상위 이유→전략 태그 · `Δindex` · E/R(WWI·분산 기반) · 리스크리턴 좌표 |
| 보유 리스트 추천 | 보유작 1편 → safe/frontier/conquer 주도 후보 3열(각 `reasons` 1줄) |
| ⑧ NAV/레벨 | (역방향) WWI가 ⑧에 후보를 넘겨 `Δindex` 받음 |
| 현황(command-center) | WWI 추천(필람/발굴) — 실데이터 시 일원화(HANDOFF §9-2) |

**계약:** 이 엔진은 후보별 `{wwi, reasons[], conviction, delta, discovery, avail[]}` 를 항상 제공한다. **`reasons[]`(기여도 순 분해)는 필수 — 없으면 출시 금지.** 세 추천 면은 이 객체만 신뢰하면 된다.

**엔진 ①·②와의 관계(명시):** ① 취향 = 주관 축(→safe), ② 정전가 = 객관 축(→canon). **WWI는 이 둘을 *포함한 여섯 신호*를 가중 결합하는 상위 통합기**다. ④(→gap)·⑦(→conquer)·reading·frontier가 나머지 네 다리. 단일 점수가 아니라 *분해된 논거의 합*이라는 점이 이 엔진을 다른 추천 시스템과 가른다.

## 8. 못박아야 할 미정 결정 (체크리스트)

1. **default 가중치 `w0`** — .30/.18/.15/.15/.12/.10? (PLAN의 구 4축 35/30/20/15를 6축으로 재배분 확정 필요.)
2. **이유 정규화 lo/hi** — 각 `s_r`의 0–100 매핑 캘리브레이션(코사인 분포·canon 백분위 정합).
3. **frontier θ(안전망 바닥)·dir_anchor 정의** — 0.25? "신뢰 감독" 판정선(편수·평점).
4. **conquer surface 우선순위·g(잔여)** — 잔여 1편 보너스 곡선, 라인 우선순위(거장 필모 vs 정전).
5. **슬라이더 β·default 위치** — 0.6? t=0이 균형 어디(완전 중립 vs 약한 safe)?
6. **conviction τ·표시 상한** — 유효 기여 임계, ● 만점(4? 5?).
7. **Δindex 계산 주체** — 엔진⑧ 완성 전 근사식 vs 미표시.
8. **다양성 바닥** — top N 중 frontier/gap 최소 비율, MMR λ.
9. **콜드 N_min·R_max** — "형성 중" 졸업선(①-e와 동기 8~10), "오늘 밤" 러닝타임 컷.
