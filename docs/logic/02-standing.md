# 코어 엔진 ② — 정전가 (Standing)

*개인화 로직 명세 시리즈 2/8. 작성 2026-06-25. 1차 출처를 정련한다: `handoff/07_scoring_model.md`(점수 모델 v1), `handoff/00_MASTER_HANDOFF.md`(계보 패키지). 짝: `docs/logic/01-taste-vector.md`. 마지막에 8개를 합친다.*

---

## 1. 우리가 하려는 것 (처음 듣는 사람을 위해)

**한 문장:** 한 영화가 — *당신이 누구든 상관없이* — 영화사·비평·시상의 세계에서 **얼마나 인정받았는가**를 하나의 객관적 점수로 매기는 엔진.

엔진 ①(취향 벡터)이 *주관*("나에게 맞나")이라면, 정전가는 그 **정확한 대척점, 객관**("세상이 인정했나")이다. 두 축은 의도적으로 분리된다. 왜 이 분리가 핵심인가 — **자산 비유는 "시장가"가 있어야만 성립하기 때문이다.** 주식에 *시장 가격*과 *내 매수 단가*가 따로 있듯, 영화에도 *정전가*(세상이 매긴 값)와 *내 별점*(내가 매긴 값)이 따로 있어야 한다. 그래야 보유 리스트의 핵심 지표인 **"저평가 발굴 / 정전 합치 / 고평가 실망"**(= 정전가 vs 내 별점의 차익) 이 성립한다. 정전가가 흔들리면 그 차익도 거짓말이 된다. 그래서 이 엔진의 미덕은 **안정성·객관성·설명가능성**이다 — *섬뜩하게 맞을* 필요는 없고, *언제나 같고 납득 가능*하면 된다.

또 하나의 원칙(핸드오프에서 가져옴): **정전가는 *품질·권위*만 담는다. *닮음*(사조·스타일·트로프)은 넣지 않는다.** "슬로우 시네마라서 더 좋은 영화"는 범주 오류 — 닮음은 엔진 ①/⑥(추천)의 영역이다. 정전가는 *수상·정전·영화제 선정·감독 급* 만으로 구성된다.

## 2. 목표 산출물 (사용자 경험 중심)

정전가는 사용자에게 **숫자 그대로** 노출된다(취향 벡터와 정반대 — 그건 숨기고, 이건 보여준다). 다만 항상 **두 축 + 분해**로.

| 사용자가 보는 것 | 어디서 |
|---|---|
| **"정전가 88"** (가격) | 보유 리스트 카드의 *가격* 자리, 볼 영화 후보 |
| **P 92 / D 25** (권위/발굴 두 서브점수) | 같은 카드 하단 |
| **가치 뱃지: 저평가 발굴 / 정전 합치 / 고평가 실망** | 보유 리스트 = `정전가 vs 내 별점` 차익 |
| **Prestige × Discovery 포지셔닝 산점도** | 현황 — 내 보유분이 2축 평면 어디에 모이나 |
| **"왜 88인가" 분해** — 칸 팔메 0.97 + 오스카 작품 0.96 + … | 영화 상세/툴팁 (설명가능성) |
| **커버리지·블라인드의 등급 가중** | 현황·분석 (정전가의 라인별 입력이 커버리지에 쓰임) |

**저장(영화 단위, `film_scores`):**
```
film_id, track, prestige_score, discovery_score, total_score,
components jsonb,   -- 어느 라인이 얼마 기여했는지(설명가능성·필수)
model_version, computed_at
```

**경험 품질의 기준:** 사용자가 "왜 이 점수?"를 물으면 `components`가 *한 줄로 납득*시켜야 한다. "칸 팔메 + 오스카 작품상 + S&S 정전" → 88. 블랙박스면 실패(`07` 원칙).

## 3. 활용 가능한 데이터

전부 **영화 고유·객관** 데이터. 사용자 데이터는 *전혀* 들어가지 않는다(그게 객관성의 정의).

| 데이터 | 위치 | 역할 |
|---|---|---|
| **영화-라인 멤버십** | `film_lineage` (10,238행, handoff `mappings/`) | 이 영화가 받은 상·등재. **1차 재료.** `result`(won/listed/…), `rank` |
| **라인 권위** | `lineage_lists.authority_weight`(0–1), `tier`(T1–T4) | `w_list` |
| **전략 등급** | `lineage_lists.strategic_tier`(S1–S4) | Discovery 입력(전위·프론티어) |
| **희소도** | `lineage_lists.selectivity`(IDF, 파생) | Discovery 가중 |
| **에디션 순위폭** | `lineage_editions.rank_max` | `f_position`(정전 순위계수) |
| **감독 급** | `auteurs.group`(G1–G5)→`film_auteur` | `c_director`(거장 바닥 받침) |
| **facet/위계** | `lineage_lists.facet`(festival/section/award/canon/national/movement/auteur/style), `parent_id` | 중복 제거·movement 제외 |
| **트랙(영화 유형)** | feature/documentary/animation/restoration | 트랙별 정규화 |

**주의:** `movement`·`style` facet은 정전가 계산에서 **제외**(닮음이지 품질 아님). national·canon·award·auteur·festival/section만 쓴다.

## 4. 본질적 문제 · 설계 주의점 · 방향성

### (a) 객관성의 경계 — 사용자 0%
정전가의 존재 이유는 *모두에게 같은 값*. 취향·평점·관람 여부가 1g이라도 섞이면 "시장가"가 아니다.
- **방향:** 입력은 *영화 고유 데이터만*. 개인화는 이 위에서 *비교*(내 별점 vs 정전가)로만 일어난다. 정전가 자체는 전역 1회 계산·전원 공유.

### (b) ★시간 편향 (survivorship & 누적 비대칭)
오래된 영화일수록 *축적할 시간*이 길었다 — 70년간 10번의 S&S 폴, 수십 년 수상사. 2023년작은 그럴 시간이 없었다. 순수 정전가는 **체계적으로 옛 영화 편향**.
- **방향:** ① *시대 보정* — 라인 수의 시대 기대값으로 정규화하거나, ② 동시대작은 "라인 미완"이라 점수가 낮을 수 있음을 **`developing` 플래그 + UI 라벨**로 정직히 표시. 1차안은 ②(보정 대신 정직), 시대 정규화는 캘리브레이션 단계 실험.

### (c) ★서구·정전 편향 — Discovery가 균형추인 이유
계보 데이터는 칸·오스카가 지배하고, 비서구 프론티어(FESPACO·BAFICI 등)는 정전 리스트에 적게 잡힌다. 순수 Prestige는 서구 정전을 과대평가.
- **방향:** **Discovery를 별도 축으로 분리**(합치지 않음). `selectivity`(희소도)가 높은 전위·프론티어(S2·S3) 멤버십을 Discovery로 보상. Total은 `Prestige + γ·Discovery`로 *약하게만* 합산(γ≈0.15) — Discovery가 전부를 부풀리면 안 됨. 포지셔닝 산점도에서 *2차원으로 보여주는 게 1차원 합보다 정직*.

### (d) 데이터 완전성 — "낮은 점수"와 "미적재"의 구분
정전가는 `film_lineage` 적재에 의존. 멤버십이 덜 적재된 영화는 점수가 *가짜로 낮다*(거짓 음성).
- **방향:** `computed_at`·`model_version`·`in_seed_catalog`로 *계산 안 됨/불완전*과 *진짜 낮음*을 구분. UI는 "아직 평가 안 됨"과 "정전가 낮음"을 다르게 표시. 라인 커버리지 검증(`verify.sql`)을 선행.

### (e) 포화 방지 vs 깊이 보상
팔메 하나 vs 팔메+오스카+정전 — 추가 성취가 *깊이*로 더해지되 모두가 100으로 포화되면 변별력 0.
- **방향:** **정렬 감쇠 합**(handoff §3). 신호를 내림차순 정렬해 기하 감쇠(δ≈0.6)로 합산 → 최강 신호가 영화를 정의하고, 2·3번째가 줄어드는 비중으로 *깊이*를 더한다. 정규화 상수 C로 상위권이 100 근처가 되게 *백분위 캘리브레이션*.

### (f) 중복 계산 / 위계
칸 경쟁부문 선정(selected) ⊂ 팔메 수상(won). 둘 다 풀카운트면 이중 신용.
- **방향:** `f_result` 계수가 자동 완충(selected 0.30은 작음) + facet 위계로 *부모노드(festival 컨테이너)는 직접 멤버 제외*. 같은 영화제의 won이 있으면 같은 시상식의 selected는 흡수 고려(v2).

### (g) 트랙 분리 — 사과와 오렌지
〈센과 치히로〉(애니)와 〈도쿄 이야기〉(극영화)를 한 스케일로 비교하면 둘 다 손해. 다큐·복원도 마찬가지.
- **방향:** 트랙별(feature/documentary/animation/restoration)로 **PrestigeScore 내부 정규화**. 교차 비교는 신중히(같은 트랙 안에서의 정전가가 1급).

### (h) 캘리브레이션은 경험적
δ·C·γ·`f_result`·감독 댐핑은 *코퍼스로 튜닝*해야 의미가 산다("상위 영화 ≈ 100, 중앙값 ≈ 50").
- **방향:** 검증 영화(〈기생충〉≈88, 〈브로크백〉·〈쉰들러〉 19개 라인 등)로 기준점을 잡고 백분위 캘리브레이션. 상수는 *가설*, 형태만 고정.

### (i) movement/style 제외 (재확인)
사조·스타일은 정전가에 **안 들어간다**. 이건 닮음(엔진 ①/⑥)이지 품질이 아니다.
- **방향:** 계산 시 facet 화이트리스트(award·canon·national·auteur·festival·section)만. 단 `value.debut`(신인상)는 정전가 미반영·**Discovery/신진**에 가산.

### (j) 정전가 vs 내 별점 = 자산 비유의 심장
정전가의 가장 중요한 *소비처*는 보유 리스트의 가치 뱃지. `gap = 내별점×10 − 정전가`.
- **방향:** 이 차익이 깨끗하려면 정전가가 0–100 스케일에 잘 캘리브레이션되어야 한다(별점 1–10 ↔ 정전가 0–100 정합). 임계(발굴 gap≥+12, 고평가 ≤−9)는 엔진 ⑤/보유에서 확정하되, *전제는 정전가의 신뢰성*.

### (k) "Total로 합칠 것인가"
Prestige·Discovery를 1개 숫자로 합칠지(Total*), 2축으로 둘지.
- **방향:** **2축 유지가 기본**(포지셔닝 산점도). Total은 정렬·"정전가" 단일 표기가 필요할 때의 *선택적 1D 붕괴*(`Prestige + γ·Discovery`). 표시는 P/D 둘 다 보이고, 가격 자리에 Total.

## 5. 권장 설계 (1차안 — handoff/07 정련)

> 상수는 가설. 형태를 고정한다.

**신호별 기여** (영화가 가진 라인 멤버십 i):
```
c_i = w_list × f_result × f_position           (0 ≤ c_i < 1)
w_list   = lineage_lists.authority_weight       # 0–1
f_result : won 1.0 · runner-up 0.60 · nominated 0.45 · listed 0.45 · selected 0.30
f_position(정전만) = 0.5 + 0.5·(1 − (rank−1)/max(rank_max−1,1))   # 1위≈1.0, 최하≈0.5
감독 기여  c_director = authority_weight(group) × 0.6              # 거장 바닥
```

**PrestigeScore(0–100) — 정렬 감쇠 합:**
```
신호를 c 내림차순 정렬 → raw = Σ_k c_(k)·δ^(k−1)   (δ≈0.6)
PrestigeScore = 100 · raw / C                      (C≈2.42, 백분위 캘리브레이션)
```

**DiscoveryScore:**
```
DiscoveryScore = max over (S2∪S3 멤버십) of ( w_list × f_result × selectivity_norm )
```

**Total(선택적 1D):** `Total* = PrestigeScore + γ·DiscoveryScore` (γ≈0.15).

**트랙:** track별 내부 정규화. movement/style facet 제외. `components`에 라인별 기여 보존.

**예시(핸드오프 검증):** 〈기생충〉 = 칸 팔메 0.97 + 오스카 작품 0.96 + 감독 0.86 + 국제 0.80 + 감독 G1 0.55 + 칸 경쟁 0.24 → raw≈2.12 → Prestige≈88. (프론티어 없음 → Discovery 낮음.)

## 6. 트랙 · 캘리브레이션 · 갱신

- **갱신:** 영화 단위·전역 1회. 라인 적재/변경 시 해당 영화 재계산(사용자 무관 → 대량 배치). `film_scores` 머티리얼라이즈.
- **캘리브레이션:** 코퍼스 백분위로 δ·C·γ 고정. 검증셋 점검.
- **트랙:** 영화 주 유형 판정(TMDB 장르/메타) → 트랙별 정규화.
- **시대:** 1차 `developing` 플래그만, 정규화는 실험.

## 7. 다른 엔진과의 인터페이스 (이 엔진이 *내보내는* 것)

| 소비처 | 쓰는 산출물 |
|---|---|
| 보유 리스트 | `prestige/discovery/total` = *가격* · `components` = 분해 · 가치 뱃지(vs 별점) |
| 현황 | Prestige×Discovery 포지셔닝 · 라인별 정전가 → 커버리지 등급 가중(엔진 ⑦) |
| ⑤ WWI/이유 | **canon(정전 위상) 이유** = 정전가(또는 standing 백분위) |
| ④ 공백 | 라인 권위(authority)로 블라인드 *기회점수* 가중 |
| ⑧ NAV/레벨 | 보유분 정전가의 (가중) 집계가 NAV의 한 입력 |
| 프로필 | 뱃지·커버리지 표기 |

**계약:** 영화 1편당 `{prestige, discovery, total, track, components[]}` 를 제공. 사용자 데이터 없음 → 전역 캐시.

**엔진 ①과의 관계(명시):** ① 취향 벡터 = *주관*(나에게 맞나), ② 정전가 = *객관*(세상이 인정했나). 둘은 **독립**이며, 보유 리스트의 가치 뱃지·현황의 포지셔닝은 *두 축의 교차*에서 나온다. WWI(엔진 ⑤)는 이 둘을 *가중 결합*하는 상위 엔진이다(safe=①, canon=②).

## 8. 못박아야 할 미정 결정 (체크리스트)

1. **γ(Discovery 가중)** — 0.15? Total 합산 자체를 할지(2축만 둘지).
2. **δ·C** — 감쇠율·정규화 상수 캘리브레이션 목표(상위≈100/중앙≈50).
3. **시대 보정** — 정규화할지 `developing` 라벨만 둘지.
4. **트랙 정규화 방식** — 트랙별 독립 백분위? 공통 스케일+오프셋?
5. **위계 중복** — 같은 영화제 won 있을 때 selected 흡수 여부.
6. **runner-up/listed 0.45~0.60** — 비평가 차점·연간 리스트 계수 확정(`08_gap_analysis` 근거).
7. **정전가↔별점 스케일 정합** — 가치 뱃지 임계가 의미 있으려면 0–100 분포가 별점 1–10과 어떻게 대응하나.
8. **미적재 vs 저점수 UI 구분** — `developing`/`in_seed_catalog` 노출 규칙.
