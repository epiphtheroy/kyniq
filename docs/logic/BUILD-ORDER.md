## 1. 실재 감사 — 무엇이 *이미* 있나 (충격적으로 앞서 있음)

DB를 직접 조회한 결과, 기획 문서가 가정한 것보다 substrate가 훨씬 완성되어 있다.

| 자산 | 실재 | 함의 |
|---|---|---|
| **본/볼 영화 척추** | `user_movies`(user_id·film_id·**rating**·**seen**·**watchlist**·watched_at·note·visibility) | 내가 제안한 `user_films`가 *이미 이 이름으로 존재.* status enum 대신 `seen`/`watchlist` bool. → **명세의 user_films를 user_movies로 통일.** |
| **영화 시장가 (엔진②)** | `film_scores`(film_id·track·**prestige_score·discovery_score·total_score·components**·model_version) · **5,985편 산출됨** | 엔진② 명세와 *컬럼 1:1 일치.* 사실상 *이미 구현됨.* ⚠ **단 캘리브레이션 어긋남**(avg prestige 28, **p90=51** — 명작도 ~50, "top≈90"이 아님). |
| **해석 임베딩 (엔진①)** | `takes` **73,478편 전부 embedding** (published 26,975) + `figures` 18,168 전부, `meta_takes` 임베딩 | 취향 벡터 substrate **100% 준비.** framework·strength·theorist·register·trope_id·author_id 다 있음. |
| **계보 (엔진②③④⑦)** | `lineage_lists` 399(auteur160·movement67·award56·national47·canon18·festival18·section18·style15) + `film_lineage` 10,561 + `lineage_editions` 4,735 | 핸드오프 패키지가 *적재 완료.* authority_weight·selectivity·tier·strategic_tier 다 있음. |
| **스트리밍 가용 (엔진⑤/볼영화)** | `film_watch_providers`(results jsonb·countries) · 1,840편 | watchlist의 "지금 볼 수 있는 것" 실데이터 있음. |
| **다형 저장 (서재)** | `user_pins`(follow/like) + `user_saves`(entity_type·entity_ref·kind) | 서재 substrate 있음(현재 0행). |
| **기존 추천** | `film_next` 17,095(Trust Mediator) · `film_asset` 1,957(Why-watch 도시에) · `film_reception` 8,884 | 재활용 가능한 추천·근거 자산. |

### 없는 것 (진짜 빈자리)
| 빠진 엔진 | 상태 |
|---|---|
| ① 취향 벡터 | `user_taste_profile` **없음** — substrate는 100% 준비, *키스톤 공백* |
| ⑦ 커버리지 | 집계 RPC **없음** — 기존 테이블로 *즉시 계산 가능* |
| ⑤ WWI · ⑧ NAV · ③ 관련성 · ④ 공백 | **전무** (조합·상위층) |

> ⚠ **정정:** `film_affinities`는 0행이 아니라 **38,800행**(영화↔영화 유사 *이미 계산됨*). 엔진⑥은 "만들 것"이 아니라 "블렌드·검증할 것" — 아래 §1b.

## 1b. 추가 신호·관계 데이터 — 적절성 검토

실측 결과 *이미 풍부한 신호·관계 자산*이 더 있었다(사용자 지적). 각각의 *성격*과 *어디에 적절한지*를 검토한다. **핵심 원칙: MetaTake의 차별점 = 정전·해석 가치. 대중 점수는 보조여야 하며, 시장가(정전가②)를 오염시키면 안 된다** — 그래야 "또 하나의 집계 사이트"가 되지 않는다.

### (a) 외부 평점 신호 — `film_ratings` (1,942편 ≈ 29%, 평균 imdb_votes 82K, with_rt 1,282 · with_meta 928)

| 신호 | 성격 | 적절한 자리 | 절대 금지 |
|---|---|---|---|
| **imdb_votes** | 대중성·화제성 | ① 콜드스타트 정렬("다 봤을 법한 것"=고투표 우선) · ② **발굴 신호**(저투표 × 고정전가 = *숨은 정전* → Discovery②·공백④ 보강) | 정전가 코어 |
| **imdb_rating** | 대중 합의 품질 | 콜드스타트 *폴백 사전치*(계보 thin한 영화도 8.2면 0점 아님) · 맥락 컬럼 | 정전가 코어 |
| **rt_tomatometer / metascore** | 비평가 합의 | 위 + **"비평/대중 괴리" 맥락** | 정전가 코어 |

**통찰:** 대중 점수 ≠ 정전가(마블=RT95·정전 낮음, 벨라 타르=저투표·정전 높음). 그러므로 이것들은 (i) **정전가②에 안 들어가고**, 대신 (ii) 콜드스타트 폴백/정렬, (iii) *저대중성×고정전=숨은 보석* 발굴, (iv) 새 차익 **"비평가의 영화"**(정전가 high × 대중 RT low → 당신이 *비평가형 관객*일 신호 = 취향①의 보조 축)로 쓴다.

### (b) 관계·간선 데이터 — 엔진⑥이 사실상 *이미 구현됨*

| 테이블 | 행수 | 성격 | 쓰임 |
|---|---|---|---|
| **`film_affinities`** | **38,800** | 영화↔영화 *계산형* (score · `shared_meta_take_ids` 트로프 · `shared_list_ids` 계보 · `lineage_score`) | ⑥ 코어 — 내 명세의 "공유 라인+임베딩"이 이미 이 표로 존재 |
| **`film_next`** | 9,846(해소) | 영화→영화 *큐레이션형* + **`reason`**(Trust Mediator 계보 근거) | ⑥ 고정밀 간선 + 온보딩 이웃·볼영화 "관련작"의 *이유 한 줄* |
| **`director_next`** | 1,011 | 감독→감독 + reason | ⑥ 감독 상호추천(분석면 그래프) = auteur_edges의 실현 |
| **`meta_take_edges`** | 19,765 | 트로프/리딩 ↔ (relation·similarity) | 해석 그래프 — 렌즈 네비·트로프 유사(분석면) |

→ **엔진⑥ = "*블렌드·검증*."** *계산형(film_affinities, 넓음)* + *큐레이션형(film_next, 정밀+이유)* 두 소스를 결합하고, director_next·meta_take_edges를 그대로 소비. 새로 계산할 것이 거의 없다.

> 메모: `user_movies.rating` 샘플이 `3.5` → 별점 스케일이 0–5(half-star)로 보임. 목업은 1–10 가정 → **스케일 표준화 1건** 필요(가치 뱃지·취향 가중의 전제).

## 1c. 사용자 평점 — 1급(first-class) 신호 (사용자 지적 반영)

**질문 답:** 평점은 현재 **포착되지만(`user_movies.rating` · `app/api/track` · `/me`에 ★ 표시) *취향·추천에 연동되진 않는다*** — 취향 엔진①이 아직 없기 때문. 명세상으로는 이미 ①의 핵심이며, 지적대로 *더 넓게* 써야 한다. 평점은 **취향의 가장 직접적 표현** — "본 영화 ≠ 사랑한 영화"를 가르는 단 하나의 명시 신호다.

**평점이 흘러야 할 곳 (전 엔진 횡단):**

| 곳 | 어떻게 |
|---|---|
| ① 취향 벡터 | `v_loved`를 평점 가중 → 사랑한 영화 쪽으로 당김. `v_watched`(전체)와 분리하는 축 |
| 보유 가치 뱃지 | **`평점 vs 정전가`** = 저평가 발굴 / 고평가 실망 (이미 핵심) |
| ⑥ 유사 이웃 시딩 | 9점 준 영화가 5점보다 더 많은 이웃을 끌어옴(가중 시드 — 온보딩 fly-in 품질) |
| ③ 리니지 관련성 | "평점가중형" 정의(높게 준 영화가 몰린 계보 = 내 것) |
| ⑤ WWI safe | v_loved 경유로 친연도에 반영 |
| ⑧ NAV | 만족도·깊이(우량주 = 고평점 적중, 저평점 = drawdown) |
| 콜드스타트 | 평점 몇 개만 있어도 취향이 빠르게 또렷 |

→ **원칙: 평점은 '여러 weight 중 하나'가 아니라 *취향 정의의 1급 입력*.** 평점 변경 시 `user_taste_profile` dirty → 재계산 → 전 추천에 즉시 전파(엔진① §6).

### ★ 불변식 — "평점이 있으면 봤어요" (사용자 지적 반영)

*평점이 있는 영화는 무조건 **본 영화**로 간주한다 — 화면의 `seen` 플래그와 무관하게.* 안 본 영화엔 평점을 줄 수 없기 때문(논리적으로 `rating ⟹ seen`). 따라서 **모든 엔진이 공유하는 단일 "본 영화 판정" predicate**:

```sql
watched(film) := (user_movies.seen IS TRUE) OR (user_movies.rating IS NOT NULL)
```

- **①(취향 집합)·⑦(커버리지 분자)** = 이 predicate로 본 영화 수집(평점만 있고 seen=false인 행도 포함).
- **⑤(추천 후보)** = `NOT watched(film)` — *평점 준 영화는 추천 후보에서 제외*(이미 본 것을 추천하지 않음). "볼 영화 후보 = 안 본 영화".
- **온보딩** = 평점 매기면 그 순간 본 영화. 별점 클릭이 곧 "봤어요".
- **데이터 위생(선택):** 평점 입력 시 `seen=true`로 정규화하는 트리거를 둘 수 있으나, **로직은 그 플래그에 의존하지 말고 위 derived predicate를 직접 쓴다**(방어적 — 화면/입력 경로가 어떻든 일관). 엔진①·⑦ 명세의 "본 영화 집합" 정의에도 이 predicate를 적용한다.

⚠ **선행 1건 — 스케일 표준화:** DB/앱은 **0–5 별점(half-star, /me ★3.5)**, 목업·명세는 1–10 가정. ①의 가중식 `max(0, rating−6)`은 1–10 기준 → **0–5에선 중립점이 달라짐.** 내부 0–10 정규화(표시는 별 5)로 통일하고, 모든 평점 가중식을 *스케일-인지*로 작성. (W1 착수 전 확정.)

## 2. 본질 — "자산이 말이 되는 최소 고리"

모든 기능이 필수는 아니다. *자산운용이 한 바퀴 말이 되려면* 딱 이 고리만 있으면 된다:

```
본 영화를 기록한다(user_movies ✓)
   → 각 영화에 시장가가 있다(film_scores ✓, 단 재캘리브레이션 필요)
   → 내 취향을 안다(취향 벡터 ① — 만들어야 함)
   → 그래서 "다음 한 편"을 *이유와 함께* 추천한다(WWI ⑤ 최소판)
   → 내 현황을 본다(커버리지 ⑦)
```

이 다섯이 *서로 맞물려 한 문장*이 되면 제품이 선다. 나머지는 전부 이 고리의 *증폭*이다.

핵심 관찰: **시장가·임베딩·계보·스트리밍·척추가 다 있다.** 빠진 건 *그것들을 사용자에게 연결하는 위층*(취향 → 추천)뿐이다. 그래서 작업이 생각보다 짧다.

## 3. 지금 *안 하는* 것 (정직한 비필수)

본질이 아니면 미룬다. 좋은 설계는 *덜 만드는 것*이다.

- **동행(이중 노출) SNS** — 매력적이나 핵심 자산 고리와 무관. 취향 벡터(①)만 있으면 나중에 싱크율로 즉시 붙음. **보류.**
- **엔진⑧ NAV의 반-게이밍·P&L 정교화** — NAV는 *최소 정의*(가중 커버리지)로 시작. 적중률·자산곡선·속도검사는 데이터 쌓인 뒤.
- **엔진④ 공백의 정교한 축별 가중·생산성 판정** — 1차는 "권위×미답" 단순판.
- **엔진③ 4정의 블렌드** — 1차는 *과집중(over-index) 하나*만(가장 차별적). 나머지 3정의는 토글 v2.
- **순위(podium)·가치 뱃지 임계 미세조정·프로필 공개 투영** — UI 마감 단계.
- **혼합(k-means) 다중 취향, recency 드리프트** — 단일 벡터로 출발.

## 4. 작업 순서 (의존 순 · W0→W4)

| 단계 | 무엇 | 왜 필수 | 데이터 현황 | 만들 것 | 수용 기준 |
|---|---|---|---|---|---|
| **W0** | **엔진② 재캘리브레이션** | 시장가가 깨져 보이면(명작 51) 자산 비유 전체가 무너짐. *이미 있는 걸 고치는* 가장 싼 고가치 작업 | `film_scores` 5,985 + components | δ·C 재조정 또는 백분위 매핑 RPC. *재계산 아님, 스케일만* | 기생충·도쿄이야기 등 정전 ≈ 85–95, 중앙값 ≈ 50 |

**의존선:** W0·W1은 병렬 가능(서로 무관). W2는 즉시. W3는 ①②⑦을 먹으므로 그 뒤. W4는 전부 뒤.

## 5. 첫 걸음 제안

두 갈래가 동시에 가능하다(병렬):
- **W0 — 엔진② 재캘리브레이션 진단:** `film_scores` 분포를 더 파서 *왜 p90이 51인지*(C 과대 vs 코퍼스가 실제로 minor) 규명 → 백분위 매핑 or 상수 재조정 설계. (읽기만으로 진단 가능)
- **W1 — 엔진① 취향 벡터 설계 확정:** 실 스키마(user_movies.rating 스케일, takes.framework 분포)에 맞춰 명세 §5 공식을 *실행 가능한 SQL/RPC 초안*으로 구체화.

둘 다 *읽기·설계*만으로 진행되며 DB를 건드리지 않는다(적재·DDL은 당신 승인 후).

> **권장 시작점: W1(취향 벡터)** — 빠진 키스톤이고 substrate가 완벽히 준비돼 있어 가장 큰 잠금을 푼다. W0(재캘리브레이션)는 병렬로 진단만 먼저.

## 6. 한 줄
**substrate는 거의 다 있다 — 시장가(②)·해석 임베딩·계보·스트리밍·척추(user_movies)·*유사 그래프(⑥ 38,800)*·영화/감독 간선·외부 평점까지. 빠진 건 "취향 → 추천"의 위층 한 겹뿐이다.** 그래서 본질은 ①취향 벡터를 세우고, ②시장가 스케일을 고치고, ⑦커버리지를 잇고, ⑤최소 추천으로 고리를 닫는 것 — 딱 그만큼이다. 대중 평점(imdb/rt/meta)은 *콜드스타트·발굴·비평가형 신호*로만 쓰고 정전가엔 절대 안 섞는다.
