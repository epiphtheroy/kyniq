## ① 요약 (한 화면)

**무엇을 붙이나.** Cinecodex는 영화 *내부 미학*을 재는 새로운 점수 계열이다 — 3축(V 획득가치·C 진입비용·R 위험), 파생(U=V−λR·S 샤프), **10단계 미적 경험 분류**, **13 서브점수**(각 레벨·근거 1줄·비교작 3편). my_room의 기존 자산 계열(정전가·NAV·WWI·Δindex·가치뱃지)과는 **다른 축**이다.

**핵심 전제 — 두 가지를 절대 섞지 않는다.**
1. **자산 축(외재) vs 미학 축(내재).** 정전가/NAV/WWI = "내 컬렉션 시장가·적합도". Cinecodex V/C/R = "영화 자체의 미적 수확·진입비용·실망위험". 이 둘은 *나란히* 표시하되 한 숫자로 합치지 않는다.
2. **우리 점수 vs 외부지표 vs 정전가.** Cinecodex 문서의 비섞임 원칙(대시보드, not composite). 별개 칸에, 외부지표는 "제3자" 라벨로 시각적 종속, 정전가는 "검증 패널"로만(공식 미투입).

**가장 큰 UX 기회.** my_room은 이미 **위험을 모르고 추천한다** — WWI는 "나에게 맞나"만 답하고 "실망할 확률"은 안 답한다. Cinecodex R/U/S가 이 빈칸을 채운다. 핵심 신규 진입점은 **영화별 "Cinecodex 평가 카드"**(전체 인스펙터 + 풀페이지) 하나, 그리고 위험을 watchlist·analysis에 주입하는 것.

**가장 큰 리스크.** ⚠ **점수 인플레이션** — 화면에 정전가·NAV·WWI·V·C·R·U·S·외부 3종·10레벨·13서브가 동시에 뜨면 사용자가 *무엇을 봐야 할지 잃는다.* 해결: **점진 공개(progressive disclosure)** — 카드는 3축+레벨만 기본 노출, 13서브·신뢰도·외부지표는 접이식(셸의 4단 접이 철학과 동형).

**표시 원칙 신규 제안 (SHARED-STANDARD S11~S14, 아래 §⑤).** 비섞임 3칸 규약 · 신뢰도 흐림/플래그 · 위험 색 토큰 · μ–σ 평면 규약. **이건 디자인 결정이라 SHARED-STANDARD 소유자 승인 필요** `[⚠COORD]`.

## ④ ABSORB — 빌드 순서 (UX 관점, 의존도순)

1. **표시 규약 확정 (SHARED-STANDARD S11~S14, §⑤).** 모든 화면이 의존 → **0순위.** 색·칸·흐림 규칙 먼저 못 박아야 페이지가 안 싸운다.
2. **B형 인스펙터 요약 카드.** 가장 작은 단위, 셸 변경 0, icard만 추가. 데이터 모델(V/C/R/U/S/level/외부/신뢰도) 1개로 이후 전부 재사용.
3. **watchlist MODIFY** (U/R 컬럼·위험 필터·정렬). 위험 가치를 *가장 빨리 체감*시키는 표면. B형 카드를 인스펙터에 물림.
4. **A형 풀페이지** (`mockup-film-cinecodex.html`). B형 데이터 모델 확장 + 10레벨·13서브 전개 + 비섞임 3칸 + 신뢰도. 가장 무거움.
5. **analysis μ–σ 평면 + 위험 프로파일.** 포트폴리오 집계 — 개별 카드(2~4) 완성 후 굴려야 데이터 일관.
6. **collection 미학뷰 토글 + μ–σ 미니.** analysis μ–σ 컴포넌트 재사용.
7. **command-center 요약 주입** (KPI·today·티커). 다른 페이지 점수 안정 후 마지막에 surface.
8. (후순위) λ 다이얼 글로벌화, asset-desk 고샤프 리스트, profile 공개 집계.

**왜 이 순서:** 작은 재사용 단위(B형 카드) → 단일 페이지 검증(watchlist) → 풀 표면(A형) → 집계(analysis) → 파생 뷰(collection/command). 표시 규약이 0순위인 이유는 *되돌리기 비용*이 가장 크기 때문.

## ⑤ CONFLICT · COORD `[⚠COORD]`

**`[⚠COORD-1] 색 의미 충돌 — `--conquer` red 재사용.**
SHARED-STANDARD S2가 못 박음: **빨강=정복했다 / 앰버=아직 안 갔다.** 그런데 위험(R)을 색으로 표시하면 "고위험=red"가 자연스럽다 → red가 *정복*과 *위험* 두 의미를 가짐. **충돌.**
- 옵션 A: 위험 전용 새 토큰 `--risk:#D2453E`(red 계열이지만 별색) 신설.
- 옵션 B: 위험 = 채워진 경고 배지(아이콘 ⚠ + 숫자)로 표현, 색 의존 줄임.
- **결정 필요: SHARED-STANDARD 소유자.** (제안: 옵션 A + S12에 명문화.)

**`[⚠COORD-2] 신규 표시 규약 4종 — SHARED-STANDARD 추가 승인.**
- **S11 비섞임 3칸 규약:** 우리 점수 / 외부(제3자) / 정전가(검증) = *물리적으로 분리된 칸 또는 카드.* 한 행·한 막대·한 숫자에 두 출처 절대 병합 금지. 각 칸 하단에 출처 라벨(◀우리 계산 / ◀입력 아님 / ◀검증·미투입).
- **S12 위험 색·배지:** [COORD-1] 결과 토큰. R 구간 임계(예: <30 저 / 30–60 중 / >60 고) 정본화.
- **S13 신뢰도 흐림/플래그:** 낮은 신뢰 점수 = **opacity 0.55 + 점선 테두리 + ⚠ 플래그칩.** flagged 항목은 "재검토 중" 마이크로카피. 재현성 메타(sd·model·prompt_sha)는 `.gloss` hover 또는 접이식 카드.
- **S14 μ–σ 평면 규약:** 축 고정 = **V 세로(0–100, 위=좋음) · R 가로(0–100, 오른=위험).** 사분면 라벨·내 평균 점 표기 통일(analysis·collection 공유). command-center scatter 패턴 상속.
- **결정 필요: SHARED-STANDARD 소유자 + 백엔드(신뢰도 메타 필드 존재 전제).**

**`[⚠COORD-3] 점수 인플레이션 — 정보 위계 정책.**
한 화면 최대 노출 점수 수 상한이 필요. **제안 정책:** 기본 화면엔 *축 점수(V/C/R 또는 U/S)만*, 13서브·외부·신뢰도는 **반드시 접이/드릴다운 뒤**. 이건 페이지 디자이너 자율로 두면 페이지마다 달라짐 → 정책 1줄 필요. **결정: UX 리드.**

**`[⚠COORD-4] 공개 프로필 노출 범위.**
profile(라이트 공개)에 Cinecodex를 얼마나? **제안:** 집계(평균 V·위험 성향)만, **13서브·신뢰도 메타·flagged·prompt_sha는 운영(다크) 전용.** 외부 공개 시 "비트 결정론 미주장" 고지 동반. **결정: 제품/법무 + 백엔드(공개 뷰 RPC).**

**`[⚠COORD-5] 정전가 칸의 이중 역할.**
collection은 정전가를 *가격 컬럼*으로 쓰는데, Cinecodex 비섞임 3칸에선 정전가가 *검증 기준 칸*이다. 같은 "정전가"가 두 맥락에서 의미가 다름(거래소 가격 vs 순환성 회피 검증값). 사용자 혼란 위험 → 라벨 구분 필요("정전가·가격" vs "정전가·검증 r"). **결정: UX 리드 + 카피.**

**`[⚠COORD-6] λ 다이얼 — 글로벌 상태 vs 화면별.**
U=V−λR의 λ를 사용자가 조정하면(0.5–1.0) watchlist 정렬·analysis μ–σ·카드 U가 모두 바뀐다. 이게 **세션 글로벌 설정인지 화면별인지** 정해야 일관. **결정: UX 리드 + 백엔드(상태 저장 위치).**

## ⑥ OPEN QUESTIONS

1. **데이터 가용 시점.** 6,000편 전수 채점은 아직 실행 전(HANDOFF §8 = 다음 작업). UX는 *부분 커버리지*를 어떻게 다루나? → "Cinecodex 미평가" 상태 표시 필요(가용성 "미확인" S3 패턴 차용 가능). **카드의 빈 상태 디자인이 누락된 설계 구멍.**
2. **U/R 라벨 한국어.** V=획득가치·R=위험·U=순가치·S=샤프 — 운영 셸은 다크·전문가용이라 괜찮지만, 사용자 검증 필요. "샤프(Sharpe)"는 금융 용어 차용 — `.gloss` 정의 필수(S5).
3. **10레벨 막대 표현.** 10단계를 막대 1개로? 도넛? 사다리? — A형 와이어는 가로 10칸 막대(현 점수 막대와 동형)로 가정했으나 *순서형(ordinal)*이라 연속 막대가 오독될 수 있음. (레벨3과 레벨9의 "거리"가 막대 길이로 보임.) **시각 형식 미결.**
4. **비교작 칩의 깊이.** 13서브 × 비교작 3 = 39편 + 레벨 비교작 5 = 한 영화당 ~44개 비교작 링크. 클릭 시 *그 영화의 Cinecodex 카드*로 무한 드릴? 라우팅·성능 정책 필요.
5. **위험 색 vs 기존 P&L.** my_room에 "regret/P&L" 개념(저평점=후회)이 collection 티커에 이미 존재. Cinecodex R(사전 위험)과 P&L(사후 후회)은 *다른 것* — 사용자가 혼동 안 하게 분리 카피 필요.
6. **panel_disagree·flagged의 시각적 우선순위.** 신뢰도 낮은 점수를 흐리게 하면(S13) 정작 *논쟁적인(POLAR 높은) 흥미로운 영화*가 시각적으로 죽는다. "분열적 ≠ 신뢰낮음"인데 둘 다 흐려질 위험. flagged(신뢰)와 POLAR(분열)의 시각 구분 미설계.
