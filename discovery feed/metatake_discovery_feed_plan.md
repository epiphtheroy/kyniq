# metatake "이번 주 발견" — 큐레이션 발견 피드 기획서

> 목표: 새로 태어나는 영화 관련 사이트를 남보다 먼저 발견 → **사람이 큐레이션** → metatake에 정말로 소개 → 자연스러운 역방향 발견·백링크·관계 형성.
> 원칙: **양이 아니라 질.** 주당 최상위 10~20개만, 진짜 에디토리얼 코멘트와 함께. 이 "사람의 취향"이 스팸과 큐레이션을 가르는 방어선이자 metatake의 자산이다.

---

## 0. 먼저 — "내가 안 보내도 상대는 백링크를 어떻게 아나?"

이메일을 안 보내도 상대가 알게 되는 경로는 실제로 여러 개다. 개입이 적은 순서로:

**A. 아무것도 안 보내도 아는 경로 (수동적)**
- **리퍼러 유입**: 진짜 독자가 metatake의 링크를 클릭하면, 상대 애널리틱스(GA4 등)에 `metatake.net`이 **정상 리퍼러**로 뜬다. (핵심: 이건 사람이 실제로 온 것이라 스팸이 아니다. 리퍼러 스팸과의 결정적 차이 = "진짜 트래픽")
- **검색엔진 백링크 리포트**: 구글/Bing이 metatake를 크롤하면서 링크를 발견 → 상대의 **Google Search Console / Bing Webmaster Tools "외부 링크(Links to your site)"** 리포트에 `metatake.net`이 등장한다. 대부분의 운영자가 백링크를 이렇게 알게 된다.
- **백링크 모니터링 도구**: 상대가 Ahrefs·Semrush·Moz 등을 쓰면 "새 백링크" 알림을 받는다.
- ⚠️ 단점: **느리고, 상대가 콘솔·도구를 안 보면 영영 모를 수 있다.** ("안 보내면 어떻게 아냐"의 정직한 답 = 볼 수도, 못 볼 수도 있다. 그래서 통지를 얹는다.)

**B. 표준 프로토콜로 자동 통지 (스팸 아님 — 합의된 채널)**
- **Webmention** (IndieWeb 표준): metatake 페이지가 상대를 링크하면, 상대의 webmention 엔드포인트로 "내가 당신을 언급했습니다"라는 신호를 자동 전송. 상대가 지원하면 자동으로 알림을 받는다. → **"이메일 안 보내고 자동으로 알리는" 가장 깔끔한 정답.**
- **Pingback** (구형, WordPress 등): 상대가 워드프레스면 핑백으로 자동 통지된다.
- 리퍼러 스팸과 근본적으로 다른 이유: **수신자가 받기로 합의한 표준 채널**로, "링크했다"는 사실만 정중히 전한다. 로그 조작·자동 클릭이 아니다.

**C. 정중한 개인 메일/DM (가장 확실 + 관계 형성)**
- 반자동(템플릿 + 개인화)이되 대량 발송이 아님. 주 10~20건 규모라 한 건 한 건이 진짜다.

**권장 조합**: A는 자연히 깔리고, B(webmention)를 자동으로 쏘고, 정말 소개하고 싶은 곳엔 C(개인 메일). → **스팸 없이, 내가 굳이 전부 안 보내도, 상대가 알게 되는** 구조.

## 1. 파이프라인 개요

```
[1 수집] → [2 필터] → [3 확인·분류] → [4 사람 큐레이션] → [5 발행] → [6 통지] → [7 측정·개선]
 certstream    키워드/TLD     홈페이지 fetch      승인/에디토리얼      피드+RSS      webmention     백링크 회수율
 CZDS diff     규칙 컷        LLM 품질판별        코멘트 작성         +뉴스레터      +선별 메일      필터 개선 루프
```

하루 수천 후보 → 필터 후 수십~수백 → 확인·분류 후 20~60/주 → 사람이 최종 **10~20/주** 선정.

---

## 2. 단계별 상세

### 1) 수집 (Ingest)
- **certstream** 실시간 WebSocket(`domains-only` 스트림): 새 인증서 = 새 도메인. 자체 호스팅 권장(공개 서버 불안정).
- **CZDS 일일 zone diff**: `.film` / `.movie` / `.cinema` 존은 **전수 수집**(영화 전용 TLD라 거의 다 후보). `.com`/`.net`은 어제↔오늘 diff에서 영화 키워드만.
- 산출: 후보 도메인 원시 스트림 → append-only 테이블(`candidates`)에 적재.

### 2) 필터 (값싼 규칙으로 1차 컷)
- 도메인 문자열 규칙 사전: `film, films, cinema, cine, cinephile, movie, kino, reel, screen, frame` + 감독·영화제·평론 용어 사전.
- `.film/.movie/.cinema` TLD는 무조건 통과.
- 노이즈 컷: 파킹 패턴, 명백한 스팸, metatake 유사도메인(이건 별도 '브랜드 감시'로).
- 산출: 하루 수천 → 수십~수백.

### 3) 확인·분류 (Enrich / Classify — 실제로 열어본다)
- 각 후보 홈페이지 **1회 fetch** (예의: robots.txt 존중, rate-limit, 정직한 User-Agent 예: `metatake-discovery-bot`).
- 추출: `<title>`, meta description, 언어, 대표 텍스트, 스크린샷.
- 판별: 빈 페이지·파킹·스팸 제거 → **LLM 분류**(Claude): "영화 비평/제작/저널/아카이브 사이트인가? 주제·품질·언어?" → 0~100 점수.
- 기존 보유 도메인 set과 대조해 중복 제거.
- 산출: "사람이 볼 가치 있는" 후보 20~60/주.

### 4) 사람 큐레이션 (핵심 자산)
- 관리자용 간단 대시보드: 후보 카드(스크린샷 + 요약 + 링크 + LLM 점수) → **승인 / 보류 / 버림**.
- 승인 시 **에디토리얼 코멘트 1~2문장 직접 작성** ("왜 볼 만한가"). ← **스팸과 큐레이션을 가르는 결정적 지점.**
- 주당 **10~20개** 선정.

### 5) 발행 (Publish)
- metatake에 **"발견 / Discoveries"** 섹션/페이지 신설.
- 각 항목: 사이트명 + 정상 `<a href>` 링크 + 스크린샷 + 에디토리얼 한 줄 + 태그(감독/장르/유형).
- **RSS + 뉴스레터**로도 발행 → 구독자 도달 + 공유 유발.
- 자체 `sitemap.xml` / `news-sitemap.xml`에 포함 → 검색 색인.
- 링크 정책 결정: 신뢰되는 소개는 `dofollow`(백링크 가치를 실제로 줌 → 상대에게 진짜 선물), 확신 없으면 `nofollow`.

### 6) 통지 (Notify — 위 0장 참조)
- 모든 발행 항목에 **webmention 자동 발신**(상대 지원 시 자동 인지). 워드프레스 대상은 pingback.
- 실제 독자 클릭 → 상대 애널리틱스에 정상 리퍼러(자연 발생).
- **특별히 소개하고 싶은 소수**에게만 정중한 개인 메일(템플릿 아래).

### 7) 측정·개선 (Loop)
- 항목별 추적: 되받은 백링크? 유입? 답장? SNS 공유?
- 이 데이터로 필터·큐레이션 기준 튜닝.
- KPI: 주간 발견/발행 수, **백링크 회수율**, 발견 피드 유입, 뉴스레터 구독 전환.

## 3. 데이터 모델 (간단)

`candidates`
| 필드 | 설명 |
|---|---|
| domain | 후보 도메인 |
| source | certstream / czds |
| first_seen | 최초 발견 시각 |
| title, description, lang | 홈페이지에서 추출 |
| screenshot_url | 미리보기 |
| score | LLM 품질 점수 |
| status | new → filtered → enriched → queued → approved/rejected → published |
| editorial_note | 사람이 쓴 소개 문장 |
| published_at | 발행 시각 |
| notified_webmention_at / notified_email_at | 통지 이력 |
| backlink_received | 되받은 링크 여부(측정) |

## 4. 기술 스택 제안 (기존 자산 재사용)
- **수집**: certstream(파이썬 라이브러리, Docker 자체 호스팅) + CZDS(`pyCZDS`/`lanrat/czds`) 일일 크론.
- **저장**: Supabase/Postgres *(이미 연결돼 있어 그대로 활용 가능)*.
- **처리**: 파이썬 워커 + Claude API 분류.
- **큐레이션 대시보드**: metatake 프론트 스택 재사용(간단한 관리자 뷰).
- **발행**: metatake 사이트 내 섹션 + RSS 피드.
- **통지**: webmention 발신 라이브러리 / 워드프레스엔 pingback / 개인 메일은 수동·반자동.

---

## 5. 윤리·법적 가드레일 (스팸과의 경계선)
- robots.txt 존중, rate-limit, 정직한 User-Agent, 홈페이지 **1회만** fetch.
- 링크는 **진짜 소개 가치가 있을 때만.** 자동 대량 상호링크·링크팜 금지.
- webmention/pingback은 **표준 채널로만.** 리퍼러 조작·자동 클릭 없음.
- **옵트아웃 즉시 존중**: 빼달라면 바로 내린다.
- → 이 가드레일이 metatake를 "스팸"이 아니라 **"신뢰받는 발견 큐레이터"**로 만든다.

---

## 6. 단계적 출시 (MVP → 확장)
- **MVP (1~2주)**: certstream + 키워드 필터 + 수동 리뷰(스프레드시트) + 손으로 첫 "발견" 포스트 1개. 개념 검증.
- **v1**: DB + 큐레이션 대시보드 + LLM 분류 + RSS.
- **v2**: CZDS(.film/.movie) 추가 + webmention 자동 발신 + 뉴스레터 + 측정 루프.
